## 1. 原则

| # | 原则 | 说明 |
| --- | --- | --- |
| P1 | **门禁优先**：不为追求覆盖率而写测试，只为「这条契约/需求不能被悄悄破坏」而写 |

## 4. 引擎测试（重点）

### 4.1 属性测试（随机配置 × 固定种子）

对**随机组合**的合法 `GenerateConfig` 批量断言：

```
对 200 组随机合法 config：
  对每组跑 3 个不同 seed：
    ① 题量恰为 config.count
    ② 每道题的运算类型 ∈ config.ops
    ③ 每个操作数与结果都落在 config.ranges 及 max_value 范围内
       （D50：数值上界**仅** R1 = 20 / R2 = 100 / R7 = `max_value` 存在；
        R6 无上界（只要求操作数 ≥ 4 位），R3/R4/R5 由位数组合约束、不设数值上界）
    ④ 满足全部特殊约束：
         require_carry       → 加法必须发生进位（仅单一运算配置下断言）
         require_borrow      → 减法必须发生退位（仅单一运算配置下断言）
         exact_division      → 除法结果整除、无余数
         allow_remainder     → 允许有余数（但不强制）
         parentheses         → 脱式题必须含括号
    ⑤ 单卷内 signature 无重复
    ⑥ difficulty ∈ 1..5
    ⑦ 每道题 tags 非空
    ⑧ question_type=STEPWISE 时 steps 长度 ≥ 2 且首尾自洽（逐步计算的结果等于 answer）
    ⑨ question_type=FILL 时 display 含 □
    ⑩ **steps 必须左结合（从左到右）**：第 k 行就是「第 k 次折叠后的式子」；
       不得为规避越界而改写为右结合（D46）
    ⑪ 有上界的档位（R1 / R2 / R7）：按左到右展开的**每一步中间值与最终结果都 ≤ 上界**；
       会越界的题**不得生成**（D46 + D50）
    ⑫ `regenerate_one` 换题路径同样满足 ⑧ / ⑩ / ⑪（FR-E9 不得绕过 D46）
```

> **M1 实测口径**：`backend/tests/e2e`（verify 独立套件）跑 60 组随机合法 config × 2 个 seed
> （合计 ≥120 次生成、断言检查题数 ≥200），逐题判定 ①–⑫；⑩–⑫ 另由
> `test_m1_decisions_d46_d49.py` 以多 seed（8 个）独立复核。

### 4.2 确定性测试（FR-E8，**冻结契约**）

```
同 (config, seed) 连续生成两次 → 两次结果逐字段完全相同（含顺序）
不同 seed → 结果不同（抽样断言，避免退化实现）
```

> 这条是 M1 门禁的核心：只要它通过，「可复现」这个卖点就是真的。

### 4.3 单题重生成（FR-E9）

```
取已生成的 20 题：
  对 seq ∈ {0, 5, 19} 各调用 regenerate_one：
    ① 仅该 seq 的题发生变化，其余 19 题逐字段不变
    ② 新题签名与其余题均不重复
    ③ 新题仍满足 config 的全部约束
```

### 4.4 异常路径

| 输入 | 期望 |
| --- | --- |
| `exact_division=True` 且 `allow_remainder=True` | `ConfigError` |
| `ranges=[R7]` 但 `max_value=None` | `ConfigError` |
| `count=0` / `count=101` | `ConfigError` |
| 约束组合确实无解（如「20 以内 + 必须进位 + 100 题」） | `InsufficientQuestions`，且**耗时有上限**（不得无限重试） |
| `question_type=STEPWISE` 但只有一种运算且无括号 | `ConfigError` |
| `question_type=FILL` 且 `parentheses=True` | `ConfigError` |
| `regenerate_one` 的 `seq` 越界（含空 `existing`） | `ConfigError`（不是 `IndexError`，D49） |

### 4.5 里程碑独立复核：D46–D50（verify 独立实现）

> 由 `backend/tests/e2e/test_m1_decisions_d46_d49.py` 实现：**不复用实现方的任何测试**。
> D46 的「左结合」用测试侧自写的 token 级折叠重演器判定（与 `ExprInfo` 的 AST 求值是两条互不相干的路径）。

| 决策 | 断言 | 判据（实测口径） |
| --- | --- | --- |
| D46 | `steps` 严格左结合 | 第 k 行整数集合 = {第 k 次折叠值} ∪ {尚未参与运算的操作数}；首行 = 原式；行数 = 折叠次数 + 1 |
| D46 | 不得改右结合规避 | 8 个 config（R1/R2 加减、含括号、混合优先级、R6）× 8 个 seed = 776 题，0 例右结合 |
| D46+D50 | 有上界档位的每一步中间值与最终结果 ≤ 上界 | R1（≤20）/ R2（≤100）各 8 seed；R7 取 `max_value ∈ {20, 50, 999}` |
| D50 | R6 **无上界** | 只断言操作数 ≥ 1000 + 左结合；`1053 + 5408 + 9112 = 15573` 必须判为**合法** |
| D47+D49① | R5 `{×,÷}` 无括号脱式可出题 | 8 seed × count=12 全部出满；× 的位数组合顺序无关、÷ 不换序（`12 ÷ 345` 被 R4 拒绝） |
| D48 | 包根 re-export | `app.engine.generate` / `regenerate_one` 为函数，且与子模块同名对象 `is` 相等 |
| D49② | `seq` 越界 | `seq ∈ {-1, size, size+1, size+10, 10^6}` 与空 list 全部抛 `ConfigError`，且断言不是 `IndexError` |
| 纯函数纪律 | 契约 §8 | `backend/tests/e2e/test_m1_purity_scan.py` 用 **ast 节点扫描**独立复核（与 §6.3 的正则扫描互为印证） |

## 5. 判分测试（表驱动）

```python
CASES = [
    # (题目答案, 学生输入,       期望)
    ("42",      "42",            True),
    ("42",      " 42 ",          True),   # 去空格
    ("42",      "４２",           True),   # 全角 → 半角
    ("42",      "43",            False),
    ("7",       "7",             True),
    ("7余2",    "7 余 2",        True),   # 余数写法统一
    ("7余2",    "7…2",           True),
    ("7余2",    "7r2",           True),
    ("7余2",    "7",             False),  # 漏写余数
    ("18",      "18.0",          True),   # Decimal 等值
    ("(12+8)÷4","5",             True),   # 脱式只判最终答案
    ("5",       "(12+8)÷4",      False),  # 不判过程，按值比较
]
```

**必须覆盖的归一化分支**（每条一个用例，见契约 §3）：空白、全角、`*`/`x` → `×`、`/` → `÷`、中文括号、余数三写法、`Decimal` 等值。

### 8.2 D59 复验：「CSS 变量必须真的驱动版式」

**故障（用户实测）**：排版面板关掉「答题横线 / 卷头栏」后预览毫无变化，界面却提示已保存。

的 `var()` 引用次数为 **0**（隐藏靠渲染期烘死的 `data-*`，`answer_line=False` 时元素干脆不输出）。

**verify 独立复验（`backend/tests/e2e_m2/`，与 render-export 自测互不相干）**：

| 复验项 | 方法 | 实测 |

### 9.8 端口竞争：`free_port()` 的 TOCTOU 与 `WinError 10013` 的真实含义（task-33）

**① 现象（全树门禁实测，非推测）**

```
Ran 869 tests in 263.885s
FAILED (errors=1)
ERROR: setUpClass (tests.e2e_ui.test_ui_a9.TestA9FocusRingClosed)
AssertionError: uvicorn 提前退出：ERROR: [Errno 13] error while attempting to bind on
address ('127.0.0.1', 64695): [WinError 10013] 以一种访问权限不允许的方式做了一个访问套接字的尝试。
```

立刻复跑同一条命令：`Ran 872 tests in 278.784s / OK / exit=0`，`10013` 出现 **0** 次
（`869 = 872 − 4 + 1`：四条用例被这个 `setUpClass` 错误顶掉）。**偶发，但一次就足以让门禁红。**

**② 形态：TOCTOU**

四处套件各自写过 `free_port()`：

```python
with socket.socket() as probe:
    probe.bind(("127.0.0.1", 0))
    return probe.getsockname()[1]
```

它只是问内核要一个「此刻」空闲的端口就立刻关掉；到 uvicorn 真正 `bind` 之间有一段窗口，
窗口里任何东西（同进程里别的 server、Chromium 的出站连接、httpx 客户端……）都可能把这个端口
当自己的临时端口拿走 —— 本机 TIME_WAIT 状态的 `127.0.0.1` 端口常年在**百位数**。

**③ `WinError 10013` 的真实含义（三组受控对照）**

| 场景 | 结果 |
| --- | --- |
| `[A]` 端口处于 TIME_WAIT + 默认 bind | **OK** |
| `[B]` 端口处于 TIME_WAIT + `SO_REUSEADDR` | **OK** |
| `[C]` **已有活监听者** + `SO_REUSEADDR` | **`errno=13 winerror=10013`** |

→ TIME_WAIT **无害**；**10013 在这里的含义就是「端口已被别人占着」**。之所以不报 10048
（地址已在使用），是因为 **uvicorn 0.54.0 的 `Config.bind_socket()` 无条件设了 `SO_REUSEADDR`**；
Windows 的 `SO_REUSEADDR` 没有 Unix 那种共享语义，于是「已被占用」被翻译成了「访问权限不允许」。
**看到 10013 先去查占用者，不要查防火墙。**

**④ 修法与纪律（`backend/tests/_uvicorn_boot.py`）**

* `boot_uvicorn(command_for_port, *, cwd, env, ...) -> (process, port, attempts)`：起服务，
  bind 失败**换端口重试**，上限 `MAX_BOOT_ATTEMPTS = 4`（第一次 + 最多 3 次换端口）。
* **只按证据重试**：`looks_like_bind_failure(output)` 只认 `WinError 10013` / `10013` /
  `error while attempting to bind` / `[Errno 13]` / `address already in use` / `[Errno 48]` /
  `[Errno 98]` / `WinError 10048` / `10048`；`early-exit` / `timeout` **一次都不重试**，
  原样透出 uvicorn 输出。宁可窄：多认一个词，就多一分吞掉真 bug 的风险。
* 失败尝试的进程一律先收掉（不泄漏）。
* `UvicornBootError` 继承 `AssertionError`：在 `setUpClass` 里仍是 error、仍是红 ——
  **没有任何 skip 路径把「环境坏了」翻译成「跑过了」**。
* 错误信息是人话：写清「疑似端口竞争」+ 10013 的真实含义 + 每次试过的端口与原始输出 +
  `netstat -ano | findstr ":<port>"`。`first_port` 这个参数**只给负对照用**，生产调用点一律不传。

调用点：`e2e_ui/test_ui_structure.py`（`RealServer`）、`e2e_m4/_harness.py`（`UiServer`）、
`e2e_m3/test_m3_acceptance.py`（`startup_command`）、`e2e_m3/report_evidence.py`（`part_c`）。
`free_port` 仍从该模块 re-export（保留在 `__all__` 里），但它只是「起点」，不是「留位」。

**⑤ 这一条的判据（两个方向的负对照 + 复发证据）**

* 方向一「重试**真的**会发生」：真实 uvicorn + **真实 `listen()` 占位**（不是桩）。
  第一次尝试被强制指向被占端口 → 换端口后起绿；同一场景 `max_attempts=1` → **必红**
  （`UvicornBootError.port_race=True`，消息含「疑似端口竞争」）。
* 方向二「重试**不会**吞掉真故障」：喂 `app.does_not_exist:app`（非端口原因的真实提前退出）→
  **只尝试 1 次**、原始导入错误如实透出、消息里既没有「疑似端口竞争」也没有 `10013`。
  （只按「进程提前退出」就重试的实现，会把一个明确的导入错误伪装成环境问题 —— 这是本任务
  最要防的失败模式。）
* 复发证据：`discover -s backend/tests/e2e_ui -t backend` 连跑 **3 次全 `OK`**（10013 出现 0 次）；
  `backend/tests` 聚合哈希在运行窗口前后**逐组相同**（V8）。
  原始输出与报告：`backend/tests/e2e_ui/REPORT-task-33.md`、`e2e_ui/artifacts/task33-*.log`、
  `e2e_m4/artifacts/hash-task33-{pre,post}.json`。

**⑥ 方法边界**

「偶发」不可 100% 自证已消灭：本修复把它从「一次就红」变成「有证据才换端口、上限 4 次」，
这是机制层面的证据，**不是数学证明**。仍有一处 `free_port()` 保留：
`e2e_ui/test_ui_structure.py` 里 `ApiDownServer` 的 `ThreadingHTTPServer` —— 它在**同进程内**
紧接着 `bind`（窗口极小），且失败会以 `OSError` 立刻炸出、不伪装，本次**有意不扩面**，在此登记。
