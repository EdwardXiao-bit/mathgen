| # | 原则 | 说明 |

## 4. 引擎测试（重点）

### 4.1 属性测试（随机配置 × 固定种子）

对**随机组合**的合法 `GenerateConfig` 批量断言：

```
对 200 组随机合法 config：
  对每组跑 3 个不同 seed：
    ① 题量恰为 config.count
    ② 每道题的运算类型 ∈ config.ops
    ③ 每个操作数与结果都落在 config.ranges 及 max_value 范围内
    ④ 满足全部特殊约束：
         require_carry       → 加法必须发生进位
         require_borrow      → 减法必须发生退位
         exact_division      → 除法结果整除、无余数
         allow_remainder     → 允许有余数（但不强制）
         parentheses         → 脱式题必须含括号
    ⑤ 单卷内 signature 无重复
    ⑥ difficulty ∈ 1..5
    ⑦ 每道题 tags 非空
    ⑧ question_type=STEPWISE 时 steps 长度 ≥ 2 且首尾自洽（逐步计算的结果等于 answer）
    ⑨ question_type=FILL 时 display 含 □
```

### 4.2 确定性测试（FR-E8，**冻结契约**）

```
同 (config, seed) 连续生成两次 → 两次结果逐字段完全相同（含顺序）
不同 seed → 结果不同（抽样断言，避免退化实现）
```

> 这条是 M1 门禁的核心：只要它通过，「可复现」这个卖点就是真的。

### 4.3 单题重生成（FR-E9）

```
取已生成的 20 题：
  对 seq ∈ {0, 5, 19} 各调用 regenerate_one：
    ① 仅该 seq 的题发生变化，其余 19 题逐字段不变
    ② 新题签名与其余题均不重复
    ③ 新题仍满足 config 的全部约束
```

### 4.4 异常路径

| 输入 | 期望 |
| --- | --- |
| `exact_division=True` 且 `allow_remainder=True` | `ConfigError` |
| `ranges=[R7]` 但 `max_value=None` | `ConfigError` |
| `count=0` / `count=101` | `ConfigError` |
| 约束组合确实无解（如「20 以内 + 必须进位 + 100 题」） | `InsufficientQuestions`，且**耗时有上限**（不得无限重试） |
| `question_type=STEPWISE` 但只有一种运算且无括号 | `ConfigError` |

## 5. 判分测试（表驱动）

```python
CASES = [
    # (题目答案, 学生输入,       期望)
    ("42",      "42",            True),
    ("42",      " 42 ",          True),   # 去空格
    ("42",      "４２",           True),   # 全角 → 半角
    ("42",      "43",            False),
    ("7",       "7",             True),
    ("7余2",    "7 余 2",        True),   # 余数写法统一
    ("7余2",    "7…2",           True),
    ("7余2",    "7r2",           True),
    ("7余2",    "7",             False),  # 漏写余数
    ("18",      "18.0",          True),   # Decimal 等值
    ("(12+8)÷4","5",             True),   # 脱式只判最终答案
    ("5",       "(12+8)÷4",      False),  # 不判过程，按值比较
]
```

**必须覆盖的归一化分支**（每条一个用例，见契约 §3）：空白、全角、`*`/`x` → `×`、`/` → `÷`、中文括号、余数三写法、`Decimal` 等值。

## 7. 安全测试（契约 §9，**冻结**）

> 这条边界最容易在重构中被顺手破坏，必须自动化。

```
对 GET /api/student/paper/{code} ：
  ① 响应体 JSON 递归遍历，断言不存在任何键名为 answer / steps 的字段
  ② 断言题目对象仅含白名单键：seq, display, question_type
  ③ 对 POST /api/student/practice 重复同样的断言
  ④ 反向断言：老师端 GET /api/papers/{id} 必须**含** answer（防止一刀切删字段）
```

## 8. 渲染与分页测试（NFR-5）

| 断言 | 方法 |
| --- | --- |
| 单张 A4 页题块不被跨页截断 | 渲染 PDF 后检查每个题块的 bounding box 不跨页边界 |
| 六项排版参数生效 | 改 `cols_per_row` / `row_gap` / `font_size` / `page_margin` / `answer_line` / `header_bar` 各渲染一次，断言 CSS 变量与元素数量变化 |
| 预览与 PDF 一致 | 同一份 HTML 分别经浏览器与 Playwright 渲染，比对页数与题块位置容差 |
| 答案版单独成页 | `mode=answer` 渲染结果首页不含题目正文 |

**验收通道注意**：本机 LibreOffice 的 `docx → PNG` 光栅会把版心右移 1.53cm，**版式测量必须走 `docx → PDF → PNG`**（详见 `AGENTS.md`）。

## 9. 端到端场景（Playwright）

| # | 场景 | 步骤 | 期望 |
| --- | --- | --- | --- |
| E1 | 随堂练（模式 A） | 老师配置 → 生成 → 改题 → 打印 | 卷面正确、答案版正确 |
| E2 | 布置作业（模式 B） | 老师发布 → 学生扫码 → 作答 → 提交 | 学生看到得分；老师端出现该成绩 |
| E3 | 自主练习 | 学生选范围 + 滑杆题量 → 作答 → 提交 | 记录落入成绩列表 |
| E4 | 卷库复现 | 生成 → 发布 → 从卷库重新打开 | 题目与当初逐字段一致 |
| E5 | 发布后冻结 | 发布 → 尝试改题 | 返回 `PAPER_NOT_EDITABLE`；另存副本后可改 |
| E6 | 成绩导出 | 老师查看明细 → 导出 CSV | 文件行数与成绩条数一致 |
| E7 | 重复提交幂等 | 同 `attempt_uuid` 提交两次 | 只记一条成绩（DQ8） |

## 10. 性能测试（NFR-4）

| 项 | 目标 | 方法 |
| --- | --- | --- |
| 生成 20 / 50 题 | < 1s（目标 < 100ms） | 各跑 100 次取 P95 |
| 50 名学生并发提交 | 无失败、无 `database is locked` | 并发脚本 + WAL 校验 |
| 导出 50 题 PDF | < 5s（含浏览器复用） | 计时 |
