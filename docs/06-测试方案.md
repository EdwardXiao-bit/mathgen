> 本文件规定**每个模块的门禁测试**：任务未通过门禁不得进入「待验收」。
> 本文件也是课程提交第 3 份《测试文档》的**底稿**——M6 结束后据此扩写为 Word（见 §11）。

| 项 | 内容 |
| --- | --- |

## 1. 原则

| # | 原则 | 说明 |
| --- | --- | --- |
| P1 | **门禁优先**：不为追求覆盖率而写测试，只为「这条契约/需求不能被悄悄破坏」而写 |
| P2 | **可复现**：每个测试用固定种子，禁止依赖随机结果 |
| P3 | **证据化**：测试输出要能贴进证据清单（命令 + 通过数） |
| P4 | **契约测试与功能测试分开**：契约测试守字段与结构，功能测试守行为 |
| P5 | **安全边界必测**：`answer` 不下发这条不能靠人工检查 |

## 4. 引擎测试（重点）

### 4.1 属性测试（随机配置 × 固定种子）

对**随机组合**的合法 `GenerateConfig` 批量断言：

```
对 200 组随机合法 config：
  对每组跑 3 个不同 seed：
    ① 题量恰为 config.count
    ② 每道题的运算类型 ∈ config.ops
    ③ 每个操作数与结果都落在 config.ranges 及 max_value 范围内
       （D50：数值上界**仅** R1 = 20 / R2 = 100 / R7 = `max_value` 存在；
        R6 无上界（只要求操作数 ≥ 4 位），R3/R4/R5 由位数组合约束、不设数值上界）
    ④ 满足全部特殊约束：
         require_carry       → 加法必须发生进位（仅单一运算配置下断言）
         require_borrow      → 减法必须发生退位（仅单一运算配置下断言）
         exact_division      → 除法结果整除、无余数
         allow_remainder     → 允许有余数（但不强制）
         parentheses         → 脱式题必须含括号
    ⑤ 单卷内 signature 无重复
    ⑥ difficulty ∈ 1..5
    ⑦ 每道题 tags 非空
    ⑧ question_type=STEPWISE 时 steps 长度 ≥ 2 且首尾自洽（逐步计算的结果等于 answer）
    ⑨ question_type=FILL 时 display 含 □
    ⑩ **steps 必须左结合（从左到右）**：第 k 行就是「第 k 次折叠后的式子」；
       不得为规避越界而改写为右结合（D46）
    ⑪ 有上界的档位（R1 / R2 / R7）：按左到右展开的**每一步中间值与最终结果都 ≤ 上界**；
       会越界的题**不得生成**（D46 + D50）
    ⑫ `regenerate_one` 换题路径同样满足 ⑧ / ⑩ / ⑪（FR-E9 不得绕过 D46）
```

> **M1 实测口径**：`backend/tests/e2e`（verify 独立套件）跑 60 组随机合法 config × 2 个 seed
> （合计 ≥120 次生成、断言检查题数 ≥200），逐题判定 ①–⑫；⑩–⑫ 另由
> `test_m1_decisions_d46_d49.py` 以多 seed（8 个）独立复核。

### 4.2 确定性测试（FR-E8，**冻结契约**）

```
同 (config, seed) 连续生成两次 → 两次结果逐字段完全相同（含顺序）
不同 seed → 结果不同（抽样断言，避免退化实现）
```

> 这条是 M1 门禁的核心：只要它通过，「可复现」这个卖点就是真的。

### 4.3 单题重生成（FR-E9）

```
取已生成的 20 题：
  对 seq ∈ {0, 5, 19} 各调用 regenerate_one：
    ① 仅该 seq 的题发生变化，其余 19 题逐字段不变
    ② 新题签名与其余题均不重复
    ③ 新题仍满足 config 的全部约束
```

### 4.4 异常路径

| 输入 | 期望 |
| --- | --- |
| `exact_division=True` 且 `allow_remainder=True` | `ConfigError` |
| `ranges=[R7]` 但 `max_value=None` | `ConfigError` |
| `count=0` / `count=101` | `ConfigError` |
| 约束组合确实无解（如「20 以内 + 必须进位 + 100 题」） | `InsufficientQuestions`，且**耗时有上限**（不得无限重试） |
| `question_type=STEPWISE` 但只有一种运算且无括号 | `ConfigError` |
| `question_type=FILL` 且 `parentheses=True` | `ConfigError` |
| `regenerate_one` 的 `seq` 越界（含空 `existing`） | `ConfigError`（不是 `IndexError`，D49） |

### 4.5 里程碑独立复核：D46–D50（verify 独立实现）

> 由 `backend/tests/e2e/test_m1_decisions_d46_d49.py` 实现：**不复用实现方的任何测试**。
> D46 的「左结合」用测试侧自写的 token 级折叠重演器判定（与 `ExprInfo` 的 AST 求值是两条互不相干的路径）。

| 决策 | 断言 | 判据（实测口径） |
| --- | --- | --- |
| D46 | `steps` 严格左结合 | 第 k 行整数集合 = {第 k 次折叠值} ∪ {尚未参与运算的操作数}；首行 = 原式；行数 = 折叠次数 + 1 |
| D46 | 不得改右结合规避 | 8 个 config（R1/R2 加减、含括号、混合优先级、R6）× 8 个 seed = 776 题，0 例右结合 |
| D46+D50 | 有上界档位的每一步中间值与最终结果 ≤ 上界 | R1（≤20）/ R2（≤100）各 8 seed；R7 取 `max_value ∈ {20, 50, 999}` |
| D50 | R6 **无上界** | 只断言操作数 ≥ 1000 + 左结合；`1053 + 5408 + 9112 = 15573` 必须判为**合法** |
| D47+D49① | R5 `{×,÷}` 无括号脱式可出题 | 8 seed × count=12 全部出满；× 的位数组合顺序无关、÷ 不换序（`12 ÷ 345` 被 R4 拒绝） |
| D48 | 包根 re-export | `app.engine.generate` / `regenerate_one` 为函数，且与子模块同名对象 `is` 相等 |
| D49② | `seq` 越界 | `seq ∈ {-1, size, size+1, size+10, 10^6}` 与空 list 全部抛 `ConfigError`，且断言不是 `IndexError` |
| 纯函数纪律 | 契约 §8 | `backend/tests/e2e/test_m1_purity_scan.py` 用 **ast 节点扫描**独立复核（与 §6.3 的正则扫描互为印证） |

## 5. 判分测试（表驱动）

```python
CASES = [
    # (题目答案, 学生输入,       期望)
    ("42",      "42",            True),
    ("42",      " 42 ",          True),   # 去空格
    ("42",      "４２",           True),   # 全角 → 半角
    ("42",      "43",            False),
    ("7",       "7",             True),
    ("7余2",    "7 余 2",        True),   # 余数写法统一
    ("7余2",    "7…2",           True),
    ("7余2",    "7r2",           True),
    ("7余2",    "7",             False),  # 漏写余数
    ("18",      "18.0",          True),   # Decimal 等值
    ("(12+8)÷4","5",             True),   # 脱式只判最终答案
    ("5",       "(12+8)÷4",      False),  # 不判过程，按值比较
]
```

**必须覆盖的归一化分支**（每条一个用例，见契约 §3）：空白、全角、`*`/`x` → `×`、`/` → `÷`、中文括号、余数三写法、`Decimal` 等值。

## 12. 与课程《测试文档》的关系

课程提交的第 3 份交付物《测试文档》在 **M6 完成后**由本文件扩写，二者关系：

| 本文件（工程用） | 《测试文档》（课程用） |
| --- | --- |
| 门禁测试清单与断言 | 测试计划、测试用例表（输入 / 期望 / 实际） |
| 命令与断言 | 测试执行记录与环境说明 |
| 覆盖矩阵（需求 → 测试） | 需求覆盖分析、缺陷统计、测试结论 |

**扩写时需补齐**：测试用例编号表、缺陷记录表（真实发现的缺陷，而非编造）、测试环境说明、结论与遗留问题。为避免「无缺陷可写」，实现阶段**必须记录真实缺陷**（如本项目的 LibreOffice 光栅偏移坑，就是一条真实缺陷记录）。
