## 0. 一句话

老师上传 1–2 页照片 → 后端定位、校正、裁图 → 两遍识别 → 老师逐题校对 → `commit` 生成 `attempt(source="ocr")` → 成绩页与在线作答同构。全程本机 CPU、离线。

## 2. 端到端时序

| # | 步骤 | 谁做 | 输入 | 输出 | 失败分支 |
| --- | --- | --- | --- | --- | --- |
| 1 | 选卷 + 上传照片 | 老师（手机/电脑浏览器） | `paper_id`、学生标识、1–2 张图 | `batch_id` | 格式/大小不符 → 400 |
| 2 | 页序校验 | 后端 | 图片 + 二维码 | 页号映射 `page→file` | 缺页/重复/顺序错 → 400；二维码不可解 → 422 |
| 3 | 版本校验 | 后端 | 二维码里的 `checksum`/`layout` | 通过 | 不符 → 409 |
| 4 | 透视校正 | 后端 | 原图 + 四角块 | `page-N.jpg` | 校正失败 → 该页 `failed`，提示重拍该页 |
| 5 | 逐题裁图 | 后端 | `data-answer-box` 几何 | `crop-<seq>.png` | 几何缺失 → 该题 `needs_review`（不阻断批次） |
| 6 | 两遍识别 | 后端 | 校正页 | 每题两遍原文 + 一致标记 | 引擎未安装 → 503；单题空 → `needs_review` |
| 7 | 校对 | 老师 | 裁图 + 两遍原文 + 判分预览 | 每题 `final_answer` + `reviewed` | 未处理项存在 → commit 被拒 |
| 8 | 入档 | 后端 | 已全部 reviewed 的批次 | `attempt(source="ocr")` | 已提交 → 幂等返回原 attempt |
| 9 | 查看/导出 | 老师 | attempt | 成绩页、导出 | 与在线作答同构（不改现有逻辑） |

## 3. 状态机

**批次** `ocr_batch.status`：

```
pending → processing → reviewing → committed
   ↑          │            
   └──────────┘ (进程崩溃后启动时重置，继续跑)
               
另有 failed（批次级不可恢复：如全部页面都不可解）
```

**页** `ocr_page.status`：`pending → ok | failed(reason)`；`failed` 的页可被重传覆盖（回到 `pending` 只重跑该页）。

**题** `ocr_item.status`：`recognized`（两遍一致，默认自动通过）/ `needs_review`（两遍不一致或为空）→ `reviewed`（老师确认或修改）。

规则：

- `commit` 幂等：已 `committed` 再调 → 200 返回原 `attempt_id`，不重复判分。
- `commit` 前提：所有 `ocr_item.reviewed = true`，否则 409 并返回未处理 `seq` 列表。
- 单页重传只重跑该页的校正/裁图/识别，不动其他页；已 reviewed 的题若所在页被重传，回到 `needs_review`。

## 4. 执行模型

- 单进程：`ThreadPoolExecutor(max_workers=OCR_WORKERS)`，默认 1；与 uvicorn 单 worker 假设绑定（D10 本机部署）。
- 批次创建后立即返回 201，处理在后台线程；前端轮询 `GET /api/ocr/batches/{id}`（建议 800ms 一次，只取 `status`/`progress`）。
- 处理函数幂等：重跑覆盖裁图与识别结果，不产生重复行。
- 进程崩溃恢复：启动时把所有 `processing` 批次重置为 `pending` 并重新入队（`ocr_page` 保留已完成页，不重跑 `ok` 页）。
- 不引入 Redis/Celery/多进程队列；多 worker 部署不支持，写进 §14。

## 5. 数据模型（草案，进 `docs/04` 前登记）

三张新表，不动 `attempt`/`attempt_item`（除已有的 `source` 字段值新增 `ocr`）：

| 表 | 字段 |
| --- | --- |
| `ocr_batch` | `id`(uuid4)、`paper_id`、`student`、`source`(phone/scan)、`page_count`、`status`、`message`、`created_at`、`committed_attempt_id` |
| `ocr_page` | `batch_id`、`page_no`、`status`、`reason`、`raw_path`、`rectified_path` |
| `ocr_item` | `batch_id`、`seq`、`page_no`、`raw_text_p1`、`raw_text_p2`、`confidence_p1`、`confidence_p2`、`agreed`、`final_answer`、`reviewed` |

`attempt` 只在 `commit` 时生成：`source="ocr"`，逐题答案取 `final_answer`（老师确认后的值），判分走现有 `grading`。

## 6. 存储与清理

```
<data_dir>/ocr/<batch_id>/
  raw-1.jpg / raw-2.jpg        原图（保留，便于重跑与排错）
  page-1.jpg / page-2.jpg      校正后页面
  crop-12.png …                每题裁图
```

- 删除批次 = 删除整个目录 + 三张表的行（物理删除，D91）。
- 日志只写 `batch_id`/`page_no`/耗时/错误类型，**不写识别原文、不写图片内容**。
- **清理策略（Q19 定案，见 §17.1）**：草稿批次不自动删除；已提交批次的原图 `raw-*.jpg` 在 commit 后保留 7 天；总占用超过 2GB 时拒绝新上传并提示先清理。

## 7. 接口（草案）

| 方法与路径 | 说明 | 成功 | 失败 |
| --- | --- | --- | --- |
| `POST /api/ocr/batches` | multipart：`paper_id`、`student`、`files[]`（1–2） | 201 `{batch_id,status}` | 400 缺页/格式/大小；422 非本系统卷面；409 checksum/版本不符 |
| `GET /api/ocr/batches/{id}` | 批次状态 + 页 + 题（含裁图 URL） | 200 | 404 |
| `POST /api/ocr/batches/{id}/pages/{page_no}` | 重传单页（multipart 一个文件） | 202 | 400/409/422 同上 |
| `PATCH /api/ocr/batches/{id}/items/{seq}` | `{answer?, reviewed?, unreadable?}` | 200 | 404；409 已提交 |
| `POST /api/ocr/batches/{id}/commit` | 入档 | 201 `{attempt_id}`；已提交 200 | 409 未处理项列表 |
| `DELETE /api/ocr/batches/{id}` | 删除草稿（已提交的不可删） | 204 | 409 已提交 |
| `GET /api/ocr/batches/{id}/crops/{seq}` | 裁图（受控路由，非静态目录） | 200 `image/png` | 404 |

`batch_id` 只用 uuid4 并校验格式，路径拼接前拒绝任何非 uuid 输入。

## 8. 卷面标记（数据来源）

- **二维码**：每页页脚 20×20mm，纠错级别 M，内容 JSON：
  `{"v":1,"paper":"<卷号字符串>","checksum":"<16hex>","layout":"<版本>"}`。
  **不含页号**：打印时 Chromium 把 `position: fixed` 元素在每页重复，但元素内容不随页号变化；
  页号改由「上传顺序 1..N」确定，再用该页首题的 `data-seq` 与该页 `data-page` 交叉校验。
  `paper` 写卷号（如 `"2611-0001"`），`pages` 字段保留但当前不写。
- **二维码位置**：距右 24mm、距下 10mm（让出「距纸边 10–18mm」的四角块带）。
  实测：`right:10mm; bottom:10mm` 会把右下角块盖掉（`right:24mm` 后四角块采样均值 8.3/8.4/12.4/12.5）。
- **checksum 定义**：实现在 `backend/app/render/marking.py` 的 `sheet_checksum()`——对
  `canonical_payload()` 的规范化 JSON（`layout_version`/`mode`/`title`/`code`/`header_note`/
  `items` 的 `seq`+`display`/`layout` 标量，**不含 answer/steps**）取 `sha256` 前 16 位。
  渲染器与识别服务**共用同一个函数**，避免两处实现漂移；版面变化必须把 `LAYOUT_VERSION` +1。
- **四角定位块**：8×8mm 实心黑块，距纸边 10mm，每页四角各一；与二维码一样只在 `@media print` 内输出。
- **每题几何**：`backend/app/render/geometry.py` 的 `geometry_of()` 在打印媒体下量 `.q-row`/`.q-blank`
  并按 checksum 缓存（上限 16 项），`render_sheet_with_boxes()` 注入
  `data-answer-box="seq,x,y,w,h"`（页面归一化 0–1、原点左上、4 位小数）+ `data-page="<n>"`。
  普通 `render_sheet()` 不带这两个属性——屏幕预览与 PDF 版式不变。
- **须回归**：题目版/答案版分页、A9 预览几何判据、Word 导出（T-M18-02 已登记）。
  实测：20 题卷 HTML 25104 B、二维码 `cv2.QRCodeDetector` 解出
  `{"checksum":"b52edcc585b0685c","layout":"1","paper":"2611-0001","v":1}`。

## 9. 识别流程

1. **P1 全页**：校正页按 2× 放大，`rapidocr_onnxruntime` det+rec（`box_thresh=0.2`、`text_score=0.2`、`unclip_ratio=2.2`），按答案带匹配框内文本。
2. **P3 光照归一**：背景估计除法压掉反光/阴影梯度 + CLAHE，再跑同一 det+rec。
3. **一致判定**：两遍归一后**逐字相等** → `recognized`（自动通过）；不等 → `needs_review`，两遍原文都保留给老师看。
4. **兜底**：某题两遍都空 → `needs_review`，不静默判 0（D91）。
5. **归一**：`×→*`、`÷→/`、全角→半角、去无意义前导 0（`08→8`，`0` 保留）。归一函数与 `grading.normalize_answer` 分开：一个处理识别原文，一个处理判分口径。
6. **判分**：`grading.grade(question, final_answer)`；`grading` 用 `Decimal` 解析（实测支持负数与小数），但**一期卷面是非负整数**，负数/小数字符集登记为 DQ10 后续（见 §14）。

## 10. 页面与交互

**入口**：

- 老师端导航新增「拍照批改」；卷库页已发布卷上直接给按钮（带 `paper_id`）。
- 上传页 `/teacher/ocr`：移动端优先，`<input type="file" accept="image/*" capture="environment">` 调相机；桌面端可选文件/拖入。

**校对页** `/teacher/ocr/{batch_id}`：

- 顶部：批次状态与页面缩略图；差异题计数（`needs_review`）。
- 主体：左裁图（可取色放大）、右识别文本 + 判分预览；`needs_review` 题置顶，显示两遍原文差异。
- 一致项默认勾选「自动通过」，提供「一键确认全部一致项」。

**键盘**（仅 `pointer: fine` 桌面端提示）：`Enter` 确认并下一题；`Shift+Enter` 上一题；`F` 标「未作答」；`J/K` 或方向键切题；`Ctrl+Enter` 提交整批；提交前若有未处理项，按钮禁用并跳到第一项。

**移动端（Q20 定案，见 §17.2）**：`max-width: 900px` 时校对页单列（裁图在上、文本与判分在下），提交按钮 sticky 底部；裁图双指缩放 + 双击放大，不劫持页面滚动；上传页 `capture="environment"` 直接调后置相机，桌面端退化为文件选择 + 拖入。

**门禁**：入口页 lint、UI 语音门禁（禁开发者话术与内部编号）照现有规则。

## 11. 失败矩阵

| 症状 | 系统行为 | 老师看到 |
| --- | --- | --- |
| 二维码解不出 | 422，不进入识别 | 「这不是本系统打印的卷面，请重拍整页」 |
| checksum / layout 不符 | 409 | 「卷面版本与当前系统不一致，请重新打印」 |
| 缺页 / 页序错 / 重复 | 400 + 缺失页号 | 「少了第 2 页」 |
| 单页校正失败 | 页 `failed`，其余页继续 | 页缩略图红标 + 「重传这一页」 |
| 某题识别为空 | `needs_review` | 校对页置顶，两遍原文为空 |
| 两遍不一致 | `needs_review` | 显示两遍原文，老师二选一或输入 |
| 未安装 OCR 组件 | 503 | 「本机未安装识别组件，请联系管理员」 |
| commit 时有未处理项 | 409 + `seq` 列表 | 跳到第一项未处理题 |
| 磁盘写失败 | 500 + 原因 | 「无法保存图片，请检查磁盘空间」 |

## 13. 依赖与发布体积

- 依赖：`mathgen-backend[ocr]` extra = `rapidocr-onnxruntime`、`onnxruntime`、`opencv-python-headless`、`numpy`；模型随 wheel 打包（离线要求，不做首次下载）。
- **发布物默认含 OCR**：Docker 主镜像、npm 启动器、一键脚本都装 `[ocr]`；只有裸 `pip install mathgen-backend` 不含。
- 懒加载：`app/services/answer_ocr.py` 内 `_get_engine()` 首次调用才 import + 缓存；J-10-05 钉住。
- 预算：增量 ≤200MB；超了先减模型/换 headless 版 opencv，再谈可选下载（与 NFR-9 冲突，需登记新决策）。

## 14. 已知边界

- 单进程/单 worker 部署假设；多 worker 会重复处理（未做锁）。
- 局域网内无鉴权：上传接口与现有老师端同风险等级，不在 M18 解决（若要做，另立决策）。
- 只认本系统打印的卷面（二维码 + checksum），非本系统卷面一律 422。
- 一期不做：一页多卷切分、题干/过程识别、姓名学号识别、HEIC、云端兜底。
- 答案字符集一期承诺非负整数；负数/小数（`grading` 已能解析）登记 DQ10。
- 反光/低质照片人工比例可能到 20–40%（DQ9 已接受的代价）。

## 17. 第三轮定案（Q19–Q22，2026-11-13）

### 17.1 草稿保留与磁盘占用（Q19）

- 草稿**永不自动删除**：老师的校对随时可能被打断，误删一次就是信任事故。
- 已提交批次：保留 `crop-*.png` 与识别结果、`page-*.jpg`；`raw-*.jpg` 在 commit 后保留 **7 天**，由清理任务按 `created_at` 删除。
- 草稿列表显示占用（每批 MB 与总占用），提供「清理旧草稿」入口（按创建时间倒序，逐批删除，二次确认，文案写清不可恢复）。
- 总占用超过 **2GB** 时拒绝新上传：`400` + 提示先清理；不自动腾空间。

### 17.2 移动端断点与手势（Q20）

- 校对页断点 `max-width: 900px`：单列布局，裁图在上、识别文本与判分在下；提交按钮 `position: sticky` 于底部。
- 裁图双指缩放、双击放大（`touch-action: pinch-zoom`，不吞页面滚动）；放大后提供「还原」按钮。
- 键盘提示只在 `@media (pointer: fine)` 下渲染；手机不显示用不上的快捷键。
- 上传页 `<input type="file" accept="image/*" capture="environment">` 直接调后置相机；桌面端退化为文件选择 + 拖入。

### 17.3 版本号与合并方式（Q21）

- 版本 **`1.1.0`**：新增能力、向后兼容；`CHANGELOG.md` 写 `## [1.1.0]` 小节（1.0.x 只留给修补）。
- `feature/m18-ocr` 合并回 `main` 用 **`--no-ff` 合并提交**，保留 M18 开发轨迹；合并后打 `v1.1.0`。
- 分支纪律不变：合并前 `main` 不出现任何 M18 代码；阶段 2 实测与文档收口都在分支上完成。

### 17.4 阶段 2 样本配方与对照表（Q22）

**配方（20 页、240 题）**：

- **4 名学生 × 5 页**；每名学生的 5 页覆盖：自然光、台灯、逆光、阴影、轻微倾斜（±15°）。
- 笔色覆盖：铅笔、黑色圆珠笔、蓝色圆珠笔（至少各 2 名学生各 1 页）。
- 另加 **2 页打印后扫描的扫描件**（可来自其中 2 名学生），单列统计、不混进拍照子集。
- 精简方案（样本难凑时）：**2 名学生 × 10 页**；笔迹覆盖少一半、Wilson 区间变宽，但下界判定口径不变。

**对照表**：新建 `docs/阶段2-OCR样本对照表模板.csv`（列 `file,page,seq,answer`）：

| 列 | 含义 |
| --- | --- |
| `file` | 照片/扫描文件名（放 `.tmp-ocr-samples/phase2/`，不入库） |
| `page` | 页号（1 或 2） |
| `seq` | 题号（卷面编号，不是数组下标） |
| `answer` | 该题学生的真实答案（含错答；空答案写 `-`） |

填表口径：按学生卷面逐题抄，**不是标准答案**——判分对照要用「学生写了什么」，正确性由 `grading` 判。算分脚本读 CSV + 识别结果，输出「自动通过子集准确率 / 人工比例 / Wilson 95% 下界 / 判分一致率」。
