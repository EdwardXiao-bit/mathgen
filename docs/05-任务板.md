# 05-任务板

> **这是项目唯一的工作台账。** 没有登记在案的工作不存在，不能开工。
> 每个任务必须含**写域 / 依赖 / 验收标准**三要素；缺任一项视为任务卡无效。
> 状态流转与交接规则见 [`03-协作规范.md`](03-协作规范.md) §3–§4。

---

## 1. 使用规则

| 规则 | 说明 |
| --- | --- |
| R1 | 开工前任务必须在表中存在且状态为「待办」→ 认领后改「实现中」 |
| R2 | 认领时在 `负责人` 列写上角色名，**同一任务不并发认领** |
| R3 | 依赖未完成不得开工（表中 `依赖` 列） |
| R4 | 完成后改「待验收」并附 `03-协作规范.md` §8 的证据清单 |
| R5 | 验收由 **verify 或 Lead** 执行，写者不能自验（V3） |
| R6 | 打回时在任务行下补一行「打回原因」，不要删原记录 |

**状态**：`待办` / `实现中` / `待验收` / `已验收` / `打回` / `阻塞`

## 5. 完成定义（DoD）

一个任务只有**全部满足**才算完成：

1. 产出物落在**声明的写域**内，未越界修改他人文件。
2. 代码通过该模块的门禁测试（[`06-测试方案.md`](06-测试方案.md)），并附**原始输出**。
3. 若触碰 [`04-接口契约.md`](04-接口契约.md) 的冻结项 → 已有对应决策编号。
4. 若改动了 `docs/*.md` → 已重跑 `tools/build_docs.py` 重新生成 Word。
5. 遗留项已显式记录（写「无」也要写）。
6. 验收由**非写者**执行。
