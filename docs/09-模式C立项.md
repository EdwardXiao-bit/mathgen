# 模式 C 立项书：手写 OCR 批改（M18）

> 状态：**已立项（2026-11-12）**｜立项人：用户 said (m01027)「我们开始立项」；范围、部署位置、输入形态三项由用户在 (m01034) 选定。
> 本文件是**立项、范围与路线**的说明：需求正文并入 `docs/01`、设计正文并入 `docs/02` 的时机见 §9，推进顺序见 `docs/05` §5.12 的 T-M18-01…07。

## 1. 一句话

在现有「出题 → 打印 → 发卷 → 成绩」链路上，增加**模式 C**：老师用手机拍照或选扫描件上传 → 本机离线识别**每题最终答案** → 逐题人工校对 → 自动判分 → 成绩入档。全程不连公网。

## 2. 现状与缺口（均为实测）

- 文档口径：D11 定义三种批改模式，D14 把 C 明确列为后期；`docs/01:148` 的 FR-L1 只有一行、`docs/01:79` 的场景 5 只有两行流程；`docs/02:572` 写「本期无设计」。
- 代码缺口：
  - **没有上传通道**：`backend/app/routers/` 只有 attempts / exports / papers / sheet / student_routes / students / urls，全仓无 `UploadFile` 与 `multipart`。
  - **没有每题几何**：`backend/app/render/sheet.py:121-123` 只下发分页几何（`data-usable-first-px` / `data-usable-later-px` / `data-page-margin-px`）与 `data-seq`，没有每题 bbox。
  - **没有识别层**：`attempt_item.student_answer` 只是文本，判定走 `grading`；OCR 需要新增「这份答案从哪来」的来源字段与校对状态。
  - **体积预算未评估**：产物是 `py3-none-any` wheel + `python:3.12-slim` 镜像，目前不含 opencv / onnxruntime / 任何模型。
- 有利条件（这也是为什么 C 能在本系统做）：**卷面是我们自己渲染的**，A4 版心、行距、题号位置全部已知；定位不靠通用版面分析，而靠我们自己印的定位元素。判分、成绩三态、导出、成绩页均可复用模式 B 的既有实现。

## 3. 范围

### 3.1 做（第一期）

1. **两种入口**：① 老师端网页（手机或电脑浏览器）直接拍照上传；② 选择 / 拖入扫描件或相册图片上传。
2. **卷面校正**：用我们自己印的定位元素做透视校正；校正失败明确拒绝（「这不是本系统打印的卷子」），不硬猜。
3. **逐题裁剪答案区**：按渲染器下发的每题几何裁图，几何与卷面版本一起校验。
4. **识别每题最终答案**：限定字符集（数字、`+ - × ÷ = ( ) / .`），输出答案文本 + 置信度。
5. **人工校对**：逐题并排显示「裁剪图 / 识别文本 / 判分预览」，老师可改答案或标「无法识别」；**最终判定以老师确认后的答案为准**。
6. **判分与入档**：复用 `grading` 与既有成绩模型，成绩记录标注来源 `ocr`；成绩页可区分「学生端在线作答」与「纸质卷识别」。
7. **离线与隐私**：识别只在本机 CPU 完成，断网可用；图片与裁图只落本机 `<data_dir>/ocr/`，删批次即物理删除。

### 3.2 不做（第一期，写清以免反复）

- 识别题干；识别并判分脱式的**过程**（只判最终答案）。
- 非本系统生成的卷面（没有定位元素）。
- 自动识别学生姓名 / 学号——登记学生由老师在上传时选择或填写。
- 一页多卷的自动切分、班级批量排队。
- 云端 OCR / 多模态 LLM 兜底（与 D10、NFR-9 冲突，见 D89）。

## 4. 用户流程（目标态）

拍照 / 选文件 → 整页校正预览 → 逐题识别结果（裁剪图 + 文本 + 置信度）→ 老师确认或修正 → 判分 → 成绩页查看 / 导出。

失败分支：定位失败、卷面版本不符、某题识别为空或低于阈值 → 该题标「需人工」，**不静默给 0 分**。

## 5. 技术路线（推荐，spike 后定稿）

- **定位**：卷面每页页脚加一枚小二维码（内容含 `paper_id`、`page`、`sheet_checksum`、`layout_version`），四角加低对比定位块；上传后估单应矩阵把 A4 拉正。这样也顺带解决「这份图属于哪张卷」的校验。
- **每题几何**：渲染器给每个答案区输出 `data-answer-box="seq,x,y,w,h"`，与分页几何同源；经透视变换裁图。
- **识别**：三个候选，用 spike（T-M18-01）实测后选一个：
  - A. `rapidocr_onnxruntime`（PP-OCR 检测/识别，CPU 约 180ms/张、安装约 180MB；见 [RapidOCR 推理引擎文档](https://raw.githubusercontent.com/RapidAI/RapidOCRDocs/refs/heads/main/docs/blog/posts/inference_engine/which_inference.md)）——把识别字符集限定为数字与运算符，适合「打印框里的一小串手写数字」。
  - B. `pix2tex`（LaTeX-OCR，约 50MB，印刷公式强、手写弱，AGPL-3.0 需先过许可评估）。
  - C. 自建轻量 CNN 分类器（单字符 0–9 与 `+ - × ÷`，需真实样本训练；依赖最小但要样本量）。
- **预处理**：EXIF 方向 → 长边缩到 ≤1600px → 灰度 → 自适应二值化 → 形态学去掉答案框印刷边线。
- **答案归一**：`×→*`、`÷→/`、全角转半角、去空格；与快照 `answer` 用现有 `grading` 口径比对（`=` 前缀等容忍沿用现规则）。
- **置信度**：低于阈值默认勾「需人工」，不自动判分。
- **体积策略（spike 后按实测定）**：识别依赖做成 `mathgen-backend[ocr]` 可选 extra，模型文件随包数据；Docker 主镜像内含 OCR；npm 启动器按需装 extra。目标是**不用 OCR 的人安装体积不涨**。

## 6. 数据与接口变更（草案，进 `docs/04` 前须在 `docs/00` 登记）

- 表：`ocr_batch`（`id`、`paper_id`、`student`、`page_count`、`source`（phone/scan）、`status`、`created_at`）；`ocr_item`（`batch_id`、`seq`、`crop_path`、`raw_text`、`confidence`、`final_answer`、`reviewed`、`verdict`）。
- 目录：`<data_dir>/ocr/<batch_id>/`，内含 `page-<n>.jpg`、`crop-<seq>.png`、`meta.json`；删除批次 = 删目录。
- API：
  - `POST /api/ocr/batches`（multipart：`paper_id`、`student`、`files[]`）→ `201 {batch_id, pages:[...]}`；
  - `PATCH /api/ocr/batches/{id}/items/{seq}`（`{answer?, reviewed?}`）→ 校对结果；
  - `POST /api/ocr/batches/{id}/commit` → 生成 `attempt`（`source="ocr"`）并返回成绩；
  - `GET /api/ocr/batches/{id}` → 回读（含裁图 URL）。
- 渲染：`render/sheet.py` 增 `data-answer-box`；页脚二维码图由后端生成（复用现有二维码依赖）。

## 8. 验收指标（M18 完结口径，spike 后按实测微调）

- **准确率（两阶段；2026-11-12 按「样本太麻烦」的反馈定）**：
  - **阶段 1（spike 粗判，先做）**：**4 页、每页 ≥12 题**（实际做法：`docs/09` 生成的一张 20 题 A4 卷打印 4 份，4 个学生各写一份 → **80 题**，只需 4 张照片）。只回答「可行 / 不可行 / 要改档位」，**不写正式验收数**：80 题全对时 Wilson 95% 单侧下界约 **96.3%**，可以写「有统计支撑地超过 95%」；错 1 题则降到 93.2%，只能写「接近但未达标」。
  - **阶段 2（进 T-M18-06/07 之前补）**：20 页 × ≥12 题 = **240 题**、光照/角度/笔色混合，整题答案准确率 **≥95%** 才写正式验收结论；校对后判分正确率 **100%**（老师已确认）。
- **性能**：单页端到端 **≤10s**（4 核 CPU、12 题）；增量安装体积 **≤200MB**。
- **离线**：断网 + `NO_PROXY` 下完成全流程；发布物不含任何外部 URL 调用。
- **隐私**：图片与裁图只在 `<data_dir>/ocr/`；删批次即物理删除；日志不写识别原文。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 手写体差异（连笔、涂改、笔色浅） | 整题准确率不达标 | 答案框限一行、卷面加书写引导；必留校对环节；置信度阈值 |
| 拍照质量（阴影、倾斜、广角畸变） | 校正失败 | 页脚二维码 + 四角定位块；失败明确提示重拍 |
| 答案写在框外 | 识别为空 | 卷面印刷浅灰答案框与示例；为空一律标「需人工」 |
| 体积与启动变慢 | 安装体验回退 | 可选 extra + 懒加载 + 体积预算判据 |
| 依赖许可（`pix2tex` 是 AGPL-3.0） | 分发合规风险 | 优先 Apache/MIT 的 A/C 方案；B 需许可评估通过才用 |
| 非本系统卷面被误用 | 错误判分 | 二维码校验 paper + checksum，失败直接 4xx |
