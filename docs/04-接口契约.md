## 2. 出题引擎

### 2.1 `GenerateConfig`（出题参数，值对象，不可变）

```python
@dataclass(frozen=True)
class GenerateConfig:
    ops: set[Op]                      # {ADD, SUB, MUL, DIV}  非空          FR-E1
    ranges: list[RangeId]             # [R1..R7]              非空          FR-E2
    question_type: QuestionType       # ORAL | STEPWISE | FILL           FR-E5
    max_value: int | None = None      # R7 自定义上限，仅当 ranges 含 R7 时必填  FR-E3
    require_carry: bool = False       # 必须进位                          FR-E4
    require_borrow: bool = False      # 必须退位                          FR-E4
    exact_division: bool = False      # 除法必须整除                      FR-E4
    allow_remainder: bool = False     # 允许有余数                        FR-E4
    parentheses: bool = False         # 含括号（仅脱式题型有意义）          FR-E4
    count: int = 20                   # 题量，1..100                      FR-E6
```

> **字段顺序修正（v0.1 → 实现前）**：初稿把无默认值的 `question_type` 排在多个带默认值的字段之后，
> 这在 Python 中是语法错误。已将其前移到 `ranges` 之后。**字段名、类型、默认值均未改变，仅顺序修正。**
> 代码实现见 `backend/app/engine/types.py`（Lead 维护，冻结）。

**约束规则**（引擎必须校验并在违约时抛 `ConfigError`）：

| 规则 | 说明 |
| --- | --- |
| `exact_division` 与 `allow_remainder` **互斥** | 同时为真 → `ConfigError` |
| `ranges` 含 R7 时 `max_value` 必填且 ≥ 10 | 否则 → `ConfigError` |
| `question_type=STEPWISE` 要求 `ops` 至少含两种运算，或 `parentheses=True` | 否则无意义 |
| `question_type=FILL` 不允许 `parentheses=True` | V1 简化 |
| `count` 超出 1..100 | → `ConfigError` |

**档位语义（冻结，D47 + D49 + D50）**：
- **位数组合与顺序无关（仅乘法）**：`三位数 × 两位数` 同时接受 `两位数 × 三位数`。
- **除法不适用顺序交换（D49）**：`两位数 ÷ 三位数` 商为 0，被「结果 ≥ 1」排除，故交换无意义。
  R5 除法仍为「三位数 ÷ 两位数」，R4 为「两位数 ÷ 一位数」。
- **各档位上界（D50）**：R1 = 20，R2 = 100，R7 = `max_value`；**R6 无上界**（D16 只给下界「四位数及以上」，
  两个四位数相加本就是五位数），仅要求操作数 ≥ 4 位；R3/R4/R5 由位数组合约束，**不设数值上界**。
- **多选档位取并集**：任一所选档位接受即通过。
- R6 按字面「操作数 ≥ 四位数」。
- `require_carry` / `require_borrow` 仅在**单一运算**配置下断言（混合运算里「哪一次加法要进位」语义未定义）。

### 2.2 `Question`（题目，值对象，不可变）

```python
@dataclass(frozen=True)
class Question:
    expr: str            # "37 + 45" / "(12 + 8) ÷ 4"     统一用 ÷ 与 ×
    display: str         # 卷面展示形态；填空题含 □，如 "7 + □ = 15"
    answer: str          # 标准答案（已归一化的规范写法）
    steps: list[str]     # 脱式逐步过程；非脱式题为 []                  FR-E12
    difficulty: int      # 1..5                                       FR-E10
    tags: list[str]      # 考点标签，如 ["三位数乘两位数", "进位"]        FR-E11
    signature: str       # 去重签名：去空格、统一运算符、交换律归一        FR-E7
```

**字段纪律**：
- `answer` 是**数值型规范答案**（如 `42`、`7余2`、`5`）；判分前学生输入另行归一化，不要求与 `answer` 字面相同。
- **`answer` 不得是算式**（如 `(12+8)÷4`）。判分器**不对算式求值**，两侧一律按数值比较（D45）——这是保证判分可预测的关键边界。
- `signature` 只用于**单卷内去重**。`3+5` 与 `5+3`、`2×6` 与 `6×2` 必须视为同一签名（交换律归一），否则低档位题量会大量重复。
- `steps` 仅在 `question_type=STEPWISE` 时非空。

### 2.3 函数签名

```python
def generate(config: GenerateConfig, seed: int) -> list[Question]: ...
def regenerate_one(config: GenerateConfig, seed: int, seq: int,
                   existing: list[Question]) -> Question: ...
```

| 契约 | 说明 | 状态 |
| --- | --- | --- |
| **纯函数** | 不得读写文件、数据库、网络、全局可变状态 | **冻结**（C5） |
| **确定性** | 同 `(config, seed)` 必得**逐题相同**的结果（含顺序） | **冻结**（FR-E8） |
| **约束完备** | 返回的每道题都必须满足 `config` 的全部约束 | 冻结 |
| `regenerate_one` | 只用 `seq` 换掉一题，其余题保持原样；新题不得与 `existing` 任何题签名重复 | 草案 |
| 生成失败 | 约束组合可出的题不足时抛 `InsufficientQuestions`，**不得无限重试** | 草案 |
| **`steps` 顺序** | **必须左结合（从左到右）**，符合小学递等式书写惯例；**不得为规避越界而改写为右结合** | **冻结**（D46） |
| **`steps` 中间值** | **有上界的档位**（R1 = 20 / R2 = 100 / R7 = `max_value`）要求**每一步的中间值与最终结果都不超过该上界**；<br>R6 **无上界**（仅约束操作数 ≥ 4 位）；R3/R4/R5 由位数组合约束，不设数值上界 | **冻结**（D46 + D50） |
| **不满足则不出题** | 按左到右展开会越界的题**不得生成**，而不是改写成右结合 | **冻结**（D46） |
| **包根导出** | `app.engine` 必须 re-export `generate` 与 `regenerate_one`，使 `from app.engine import generate` 得到**函数**；`app.grading` 同（已符合） | **冻结**（D48） |
| `regenerate_one` 越界 | `seq` 超出范围内抛 **`ConfigError`**（而非 `IndexError`），保持包内错误词汇统一，便于 API 层统一映射为 4xx | **冻结**（D49） |

## 3. 判分

```python
@dataclass(frozen=True)
class Verdict:
    is_correct: bool
    normalized_input: str     # 归一化后的学生答案，便于老师端展示与排错

def grade(question: Question, raw_answer: str) -> Verdict: ...
```

**归一化规则**（顺序固定，实现必须可测）：

1. 去除首尾与中间空白
2. 全角数字 / 运算符 → 半角
3. `*` `/` `x` `X` → `×` `÷`；中文括号 `（）` → 半角
4. 余数写法统一：`7 余 2`、`7…2`、`7r2` → 统一内部形式
5. 数值比较用 `Decimal`（禁止浮点直接比较）

**已确认不做**：脱式题只判**最终答案**，过程不计分（过程规范性无法可靠自动判定）。此决策需在 `06-测试方案.md` 有对应测试。

**已确认不做（D45）**：**不对算式求值**。若 `answer` 或学生输入是算式，一律按「非数值」判错，两侧对称处理。
理由：一旦引入算式求值，判分就要处理运算优先级、嵌套与等价变形，边界不可穷尽；而引擎产出的 `answer` 恒为数值（契约 §2.2），该路径本不该被触发。
副作用（已知并接受）：若将来出现「答案本身是算式」的题型，需重新决策。

## 5. REST API

统一前缀 `/api`；请求与响应均为 JSON；时间统一 ISO 8601 带时区。

### 5.1 老师端

**请求体形状（冻结，D55）**——原表「关键请求字段」一列写得含糊，实现与文档曾出现分歧，现明确如下：

| 端点 | 请求体 | 说明 |
| --- | --- | --- |
| `POST /api/papers` | **平铺的出题参数**（与 `PaperDetail.config` 同构，即 `PaperConfigIn` 的字段直接作为顶层键） | `seed`、`title` 为**可选查询参数**（`?seed=&title=`） |
| `PATCH /api/papers/{id}/layout` | **平铺的排版参数**（`LayoutIn` 字段直接作为顶层键） | 不是 `{"layout": {...}}` 包一层 |
| `PATCH /api/papers/{id}/answer-layout` | **平铺的答案版形式**（`AnswerLayoutIn` 字段直接作为顶层键，D64） | **整体替换**语义，与 `/layout` 一致（D64） |
| `POST /api/papers/{id}/items/{seq}/regenerate` | 无请求体 | — |
| `POST /api/papers/{id}/publish` / `.../copy` | 无请求体 | — |

> 即：**单资源参数直接平铺**，不额外包 `{config: ...}` / `{layout: ...}`。前端与后端都按此实现。
>
> **「答案版形式」（六维中的第六维）自 M3 起接入**（D64）：`PaperDetail.answer_layout` 返回真实值，
> 通过 `PATCH .../answer-layout` 修改；已发布的卷修改返回 409 `PAPER_NOT_EDITABLE`。
> 数据库中 `paper.answer_layout` 的历史空值 `{}` 由服务层按 D20 默认补齐（老卷免迁移）。

**卷库列表的查询参数（D64）**：`limit`（1..100，默认 20）、`offset`（≥0）、`q`（按标题模糊匹配）、
`status`（`draft` / `published`，留空为全部）。响应 `PaperListOut` 含 `total`（**不受 limit/offset 影响**）、`limit`、`offset`、`papers`。

> **`page` / `size` 已移除**（D65）。它们仍以 `deprecated=True` 保留在签名里作为**迁移护栏**：
> 显式传入会返回 **422** 并提示改用 `limit` / `offset`。
> **为什么不是直接删干净**：FastAPI 会**静默忽略**未知查询参数——若只删参数，老调用方 `?page=2`
> 会拿到第一页却**以为翻页成功**。**报错好过静默错**（与「界面不许谎报已保存」同一条原则）。

**错误码区分（D65）**：按 id 查不到卷 → `PAPER_NOT_FOUND`；**按卷号查不到 → `CODE_NOT_FOUND`**（§9 原有码）。两者语义不同，不得混用。

### 5.2 学生端

| 方法 | 路径 | 关键请求字段 | 关键响应字段 | 对应 FR |
| --- | --- | --- | --- | --- |
| POST | `/api/students` | `name`, `student_no`（**均必填**，D41） | `student_id` | FR-S2 |
| GET | `/api/student/paper/{code}` | — | `paper_id`, `title`, `total`, `items[]`**（不含 answer/steps，D74）** | FR-S4 |
| POST | `/api/student/practice` | **平铺**的 `GenerateConfig` 字段（`count` 来自滑杆，D55） | `seed`、`total`、`items[]`**（不含 answer/steps，D74）** | FR-S3 |
| POST | `/api/attempts` | `student_id`, `attempt_uuid`, `answers`, `duration_ms`，且**二选一**：`paper_id` 或（`config` + `seed`） | `attempt_id`, `total`, `correct`, `items[]`（含正确答案与对错） | FR-S7/S8 |

**提交作答的两种模式（D75）**——`paper_id` 与（`config` + `seed`）**恰好给一组**，否则 422：

- **做老师发的卷**：给 `paper_id`，服务端从 `paper_item.payload` 读**完整题目快照**判分，**不重跑引擎**（D27）。
- **自主练习**：给 `config` + `seed`（`seed` 由 `/api/student/practice` 返回，学生原样回传），
  服务端用 `generate(config, seed)` **重新生成一遍**再判分。**这里依赖的正是引擎的核心保证——同种子完全可复现**；
  因此服务端**不需要**客户端回传题目内容，也就**不可能被客户端伪造题目**（例如把 1+1 冒充成本次练习的题）。
  若 `seed` 缺失或与 `config` 不匹配生成不出题 → 422，**不静默降级**。

`answers` 形状：`[{"seq": 1, "answer": "42"}, {"seq": 2, "answer": null}]`——按 `seq` 匹配，
未作答给 `null` 或整体省略该项，均按**答错**计。

**`attempt_uuid` 幂等（D76，关闭 DQ8）**：客户端每次提交生成一个新的 UUID，**必填**。
服务端按 **`(student_id, attempt_uuid)`** 去重：重复提交**不新建记录**，直接返回**首次那次的判分结果**（HTTP 200，响应体相同）。
**为什么按 `(student_id, attempt_uuid)` 而不是全局唯一**：查询永远带上 `student_id`，
所以**猜中别人的 UUID 也只会返回自己的记录**，不构成信息泄露；而全局唯一反而会让学生 B 猜中 A 的 UUID 拿到 A 的成绩。
**为什么要幂等**：教室网络抖动导致的重发、以及学生连点提交，都不该在成绩表里多记一条。

**冻结的安全契约（C2 / 契约 #9）**——原文只写了「不得包含答案性信息」，含糊到无法判定。现改为**白名单**（白名单强于黑名单：D71 的教训是**枚举式黑名单永远不完整**）：

> **学生端题目对象只允许这三个键**：`seq`、`display`、`question_type`——**逐层递归检查**，出现任何其它键即失败。
> 尤其不得出现 `answer`、`steps`（含任何嵌套形式，如 `items[].answer`、`data.steps`）。
> 取题接口**只返回题干**，判分只在服务端进行；学生若能读答案，自动判分就失去意义。
> 此契约由**自动化测试**守住（见 `06-测试方案.md` §7）：测试**递归遍历响应里每一层的键名**，
> 任一层出现白名单外的键即失败——**只查顶层是不够的**，字段一旦被包进 `item` 里就漏了。
> **反向断言**：老师端 `GET /api/papers/{id}` 必须**含** `answer`——防止有人一刀切删字段，把老师端也删了。

### 5.3 学生端 URL 与二维码（冻结，D54）

二维码必须能被手机直接扫开，因此**必须是绝对 URL**：

| 字段 | 形式 | 规则 |
| --- | --- | --- |
| `PublishResult.student_url` | **绝对** URL | 由**请求的 `Host` 头**构造（`http://{Host}/student/paper/{code}`） |
| `PublishResult.qr_url` | 相对路径 | `/api/papers/{id}/qr`，前端同源直接引用 |
| `GET /api/papers/{id}/qr` | `image/png` | 编码的正是上面的 `student_url` |

**为什么用 Host 头而不是探测本机网卡**：老师在局域网上用哪个地址访问，二维码就指向哪个地址——
老师从 `192.168.1.5:8000` 打开页面，学生扫到的就是这个地址，天然可用，且**无需任何配置或网卡枚举**，
也不会出现「服务在多个网卡上、探测到错误那个」的问题（NFR-1 局域网扫码）。

### 5.4 错误响应

```json
{ "error": { "code": "PAPER_NOT_EDITABLE", "message": "已发布的卷不能直接修改，请另存为副本" } }
```

## 6. 数据模型

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `paper` | `id`, `code`, `title`, `status`, `seed`, `config_json`, `layout_json`, `answer_layout`, `created_at`, `published_at` | `code` 唯一，仅 `published` 时非空；`status ∈ {draft, published}`；`answer_layout` 为答案版排版占位（NOT NULL，默认 `{}`），**其格式由 M3 渲染导出方定义**（D20） |
| `paper_item` | `id`, `paper_id`, `seq`, `payload`, `origin` | `UNIQUE(paper_id, seq)`；`payload` 为 `Question` 完整快照 |
| `edit_log` | `id`, `paper_id`, `action`, `seq`, `at` | `action ∈ {delete, regenerate}` |
| `student` | `id`, `name`, `student_no`, `created_at` | `name` 与 `student_no` **均必填**；`UNIQUE(name, student_no)`（同名靠学号区分，D35 / D41） |
| `attempt` | `id`, `student_id`, `paper_id`, `config_json`, `total`, `correct`, `duration_ms`, `submitted_at` | `paper_id` **可空**（空 = 自主练习） |
| `attempt_item` | `id`, `attempt_id`, `seq`, `payload`, `student_answer`, `is_correct` | `UNIQUE(attempt_id, seq)`；`payload` 冗余保存题目快照 |

**冻结语义**：

| 契约 | 说明 |
| --- | --- |
| 快照优先 | `paper_item.payload` 与 `attempt_item.payload` 存**完整题目快照**；卷库读取与历史成绩还原**不重跑引擎**（D27） |
| 冗余理由 | `attempt_item` 冗余题目快照，使卷被删除或引擎升级后历史成绩仍可完整还原（FR-T12） |
| 状态机（**冻结**） | `draft`（可删题/换题，无卷号）→ `published`（只读，有卷号，学生可做）；**不可逆**，改题走另存副本（D32） |
| 卷号（**冻结**） | `YYMM-NNNN`，如 `2510-0007`，序号按月自增（D34） |
| 删题语义 | 删除后**后续题号前移**，并在 `edit_log` 记 `deleted seq=N`；仅 `draft` 允许 |

## 7. 前端路由

| 端 | 路由 | 页面 |
| --- | --- | --- |
| 老师 | `/teacher` | 出题配置（六维表单） |
| 老师 | `/teacher/paper/:id` | 预览与改题 + 右侧排版面板（实时生效） |
| 老师 | `/teacher/library` | 卷库 |
| 老师 | `/teacher/paper/:id/publish` | 发卷（二维码 + 卷号同屏） |
| 老师 | `/teacher/paper/:id/attempts` | 成绩列表 → 逐题明细 → 导出 |
| 学生 | `/student` | 入口：姓名 + 学号 + 两个入口（自主练习 / 输卷号） |
| 学生 | `/student/practice` | 练习页：一屏一题、数字键盘、进度、计时 |
| 学生 | `/student/result` | 结果：得分 + 每题对错 |

**前端路由契约**：老师端与学生端**不得共享页面组件**，只共享 `src/shared/`（类型与 API 客户端），保证学生端打包体积不含老师端代码。

## 8. 模块依赖方向（**冻结**）

```
routers  →  services(engine / grading / layout / render / export)  →  models
   ↓                    ↑
schemas            （engine 与 grading 是叶子，不依赖任何上层）
```

| 规则 | 说明 |
| --- | --- |
| D-1 | `app/engine/**` **不得** import `app.models`、`app.routers`、`fastapi`、`sqlalchemy` 或任何 I/O |
| D-2 | `app/grading/**` 同上 |
| D-3 | `app/render/**` 与 `app/export/**` 只能依赖 `layout` 与 `engine` 的数据结构，不得直接查库 |
| D-4 | 禁止 `engine` ↔ `routers` 互相依赖，禁止循环依赖 |
| D-5 | 前端 `src/teacher` 与 `src/student` 不得互相 import，只能共同 import `src/shared` |

> 这些规则可以用一行测试守住（如 `grep` 断言 engine 目录内不出现 `fastapi` / `sqlalchemy`），建议纳入 `06-测试方案.md` 的门禁。

## 9. 错误码

| 码 | HTTP | 含义 |
| --- | --- | --- |
| `CONFIG_INVALID` | 400 | 出题参数违约（见 §2.1 约束规则） |
| `INSUFFICIENT_QUESTIONS` | 422 | 当前约束组合可出的题不足 |
| `PAPER_NOT_FOUND` | 404 | 卷不存在 |
| `PAPER_NOT_EDITABLE` | 409 | 对已发布卷做编辑操作 |
| `PAPER_NOT_PUBLISHED` | 409 | 学生端访问未发布的卷 |
| `CODE_NOT_FOUND` | 404 | 卷号无效 |
| `ITEM_NOT_FOUND` | 404 | 题目序号不存在（D53） |
| `NOT_FOUND` | 404 | 路由不存在的兜底（未匹配路径不再泄漏 FastAPI 默认 `detail`，D57） |
| `METHOD_NOT_ALLOWED` | 405 | 该接口不支持该方法（D57） |
| `NOT_IMPLEMENTED` | 501 | 功能明确未实现（D57）。**注意：`format=docx` 自 M3 起已是真实现**（D64），此处不再以它举例；该码保留给后续明确未实现的格式或能力 |
| `RENDER_NOT_READY` | 503 | 渲染模块未就绪，卷面暂不可用（D53） |
| `ATTEMPT_DUPLICATE` | 200 | 重复提交，返回原结果（幂等，DQ8） |
| `VALIDATION_ERROR` | 422 | 请求体字段校验失败 |
