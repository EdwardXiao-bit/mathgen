# 03-协作规范

> 本项目允许**多个智能体并行工作**。本文件是并行协作的硬规则，不是建议。
> 与本文件冲突的临时做法一律无效；确需例外，先写进 [`00-决策记录.md`](00-决策记录.md)。

---

## 1. 为什么需要这份文件

智能体没有共享记忆：窗口会被摘要、会被替换。**只有磁盘上的文件是可靠记忆。** 并行协作只有三个真正会翻车的地方，本文件逐条封死：

| 失效模式 | 后果 | 本文件的对应机制 |
| --- | --- | --- |
| F1 两个人改同一个文件 | 互相覆盖，改动静默丢失 | §2 写域表 + §5 冲突处理 |
| F2 接口没冻结就各自实现 | 集成时字段名/语义对不上 | §6 接口冻结与变更流程 |
| F3 没人验证，靠「我做完了」 | 缺陷进入主干，返工成本翻倍 | §7 验证纪律 + §8 证据清单 |

## 2. 角色与写域

**写域 = 该角色有权修改的路径前缀。默认一个路径同一时刻只有一个写者。**

| 角色 | 职责 | 写域（独占） |
| --- | --- | --- |
| **Lead** | 拆任务、定契约、裁决冲突、跑最终验收、维护共享文件 | `AGENTS.md`、`docs/00`、`docs/03`、`docs/04`、`docs/05`、`README.md` |
| **eng-engine** | 出题引擎：参数模型、档位、构造器、去重、难度、考点 | `backend/app/engine/**`、`backend/tests/engine/**` |
| **eng-grader** | 判分：答案归一化、等值判定、余数写法 | `backend/app/grading/**`、`backend/tests/grading/**` |
| **be-api** | 数据库模型、迁移、REST 接口、状态机 | `backend/app/models.py`、`backend/app/schemas.py`、`backend/app/routers/**`、`backend/migrations/**` |
| **render-export** | 渲染模板、排版参数、PDF / Word 导出 | `backend/app/layout/**`、`backend/app/render/**`、`backend/app/export/**` |
| **fe-teacher** | 老师端界面：配置、预览改题、排版面板、卷库、成绩 | `frontend/src/teacher/**` |
| **fe-student** | 学生端界面：入口、练习、答题、结果 | `frontend/src/student/**` |
| **docs-build** | 文档与配图构建、课程 Word 产出 | `tools/**`、`docs/word/**` |
| **verify** | 独立验证：跨模块测试、压测、离线与分页验收 | `tests/e2e/**`、`docs/06-测试方案.md` |

**共享只读区（任何人可读，改需申请）**：`docs/01-需求分析.md`、`docs/02-技术设计.md`。
**Lead 独占区**：见上表 Lead 行；其他角色需要改动时走 §5。

> 写域是**建议性约束**，靠自觉与 Lead 检查执行，不是文件锁。**看到写域外的文件，先停下问，不要顺手改。**

## 3. 任务生命周期

```
待办 ──认领──> 实现中 ──自测通过──> 待验收 ──Lead 验收──> 已验收
                    │                     │
                    └──── 阻塞 ───────────┴──打回──> 实现中
```

规则：

1. **先登记再动手**：任何改动前，任务必须在 [`05-任务板.md`](05-任务板.md) 中存在，且含写域、依赖、验收标准三要素。
2. **认领即声明**：认领时把状态改为「实现中」并写上自己的角色名。同一任务不并发认领。
3. **依赖未完成不得开工**：任务卡列了 `依赖` 就先等；抢跑出来的代码在集成时基本要重写。
4. **自测通过才提交验收**：提交时必须附 §8 证据清单，缺证据的验收请求直接打回。
5. **打回要写原因**：不是「不行」，而是「哪条验收标准、观察到什么、期望什么」。

## 4. 交接协议（Handoff）

会话切换、角色换手、任务中断时，交接内容**必须**包含下面六项。少一项就等于没交接：

| # | 项 | 说明 |
| --- | --- | --- |
| 1 | 任务 ID | 对应 `05-任务板.md` 的编号 |
| 2 | 改动文件清单 | 具体路径，不用「相关文件」这种说法 |
| 3 | 验证命令 | **可直接复制执行**的命令 |
| 4 | 原始输出 | 命令的真实输出（截取关键行），不是转述 |
| 5 | 未完成 / 遗留 | 已知的坑、TODO、未覆盖的分支 |
| 6 | 是否触碰冻结契约 | 若触碰，附决策记录编号 |

**反例（等于没交接）**：

> 「出题引擎已经写好了，功能正常，测试通过。」

**正例**：

> 任务 T-M1-01。改动：`backend/app/engine/{types,ranges,builders}.py`（新增）。
> 验证：`uv run pytest backend/tests/engine -q` → `18 passed in 0.42s`。
> 未完成：R6（四位数加减）的退位约束尚未覆盖，留 TODO 在 `builders.py:214`。
> 未触碰冻结契约。

## 5. 写域冲突处理

| 场景 | 处理 |
| --- | --- |
| 需要改他人写域内的文件 | 在任务板登记「跨域申请」，说明原因与改动范围 → **Lead 裁决** → 串行执行（前一个写者完成后再动） |
| 需要改共享只读区 | 同上，且必须同步：改 `01`/`02` 后**重新生成 Word**（D37） |
| 需要改 Lead 独占区 | 只能向 Lead 提交变更内容，由 Lead 落盘 |
| 发现两处实现矛盾 | **停下来**，在决策记录登记待决问题，Lead 裁决后再继续；不要两边同时改 |
| 紧急修复 | 允许先行修复，但必须在同一轮内补登记任务卡与证据 |

**永远不要**为了「让代码跑起来」而修改别人写域里的文件——这是本项目最容易发生的静默破坏。

## 6. 接口冻结与变更

- 接口的**唯一权威来源**是 [`04-接口契约.md`](04-接口契约.md)。`02-技术设计.md` 中的对应章节是设计说明；**两者冲突时以契约文件为准**，并同步回写 `02`。
- 契约中每一项标注状态：**冻结** / **草案**。草案可以边做边议，冻结项一个字都不能顺手改。
- 变更流程（**四步，缺一不可**）：

```
① 提案：在 00-决策记录.md 新增决策（D 编号），写明动机与影响面
② 定稿：更新 04-接口契约.md，提升版本号
③ 通知：在任务板给所有下游任务加备注
④ 同步：下游按新契约改完，并在证据清单里注明「已同步契约 vX」
```

- **禁止**「顺手改一下接口」：字段改名、默认值变化、可空性变化，都属于破坏性变更，必须走流程。

## 7. 验证纪律

> **没有人能自证完工。** 「我做完了」不是证据，可复现的命令与原始输出才是。

| 规则 | 说明 |
| --- | --- |
| V1 | 每个任务的完成都必须跑 [`06-测试方案.md`](06-测试方案.md) 中该模块的**门禁测试**，并贴出原始输出 |
| V2 | 涉及冻结契约的改动，必须跑**契约测试**（字段名、类型、可空性） |
| V3 | 关键模块（出题引擎、判分、卷状态机）由 **verify 角色独立复跑**，不能只有写者自己的测试 |
| V4 | Lead 在宣布里程碑完成前，必须**自己再跑一次**端到端验收，并保留命令与输出 |
| V5 | 可视化产物（卷面、PDF、Word）必须**实际渲染出来看过**，不能只看代码 |
| V6 | 性能类结论（NFR-4）必须给**实测数字**，不接受「应该很快」 |

**已知测量陷阱**：本机 LibreOffice Kit 的 `docx → PNG` 光栅会把版心右移 1.53cm，看起来像排版溢出。**版式验收必须走 `docx → PDF → PNG`**。详见 `AGENTS.md`。

## 8. 证据清单（任务完成时提交）

在任务卡或交接中按此表填写，**空项要写「不适用」并说明理由**：

| 证据类型 | 要求 | 示例 |
| --- | --- | --- |
| 改动清单 | 文件路径 + 新增/修改/删除 | `backend/app/engine/builders.py`（新增） |
| 构建 | 命令 + 成功标志 | `pnpm build` → `✓ built in 3.4s` |
| 测试 | 命令 + 通过数 | `pytest -q` → `42 passed` |
| 契约 | 是否触碰冻结项 | 「未触碰」或「已同步契约 v0.2」 |
| 渲染 | 产物路径 + 目视结论 | `docs/word/*.pdf` 第 3 页，版心 3.0–18.5cm |
| 性能 | 实测数字 | 生成 50 题耗时 87ms（NFR-4 要求 < 1s） |
| 遗留 | 未完成项与原因 | R6 退位约束未覆盖 |

## 9. 上下文经济

- **大范围阅读交给子代理**：子代理有独立窗口，只回结论，不把文件内容带回主会话。
- **能查的别贴**：用 `grep` / `glob` / `read` 定位，不要把大段代码或文档贴进对话。
- 长文件一律用 `offset` / `limit` 分段读，或用 `grep` 精确命中。
- 需要带着上下文继续的工作，用 `subagent_fork` 而不是重新描述一遍背景。

## 10. 命名与语言约定

| 项 | 约定 |
| --- | --- |
| 代码标识符 | 英文（`generate`、`paper_item`、`GenerateConfig`） |
| 注释 / 文档 / 提交信息 | **中文** |
| 文档文件名 | `NN-名称.md`（两位序号），如 `04-接口契约.md` |
| Python | 模块 `snake_case.py`，类 `PascalCase`，常量 `UPPER_SNAKE` |
| TypeScript | 组件 `PascalCase.tsx`，工具 `camelCase.ts`，类型 `PascalCase` |
| 任务 ID | `T-<里程碑>-<两位序号>`，如 `T-M2-03` |
| 决策编号 | `D<n>`；待决问题 `Q<n>`；设计待决 `DQ<n>` |
| 提交信息 | `<type>(<scope>): <中文说明>`，type ∈ feat/fix/refactor/test/docs/chore |
| 分支 | `<type>/<任务ID>-<简短描述>`，如 `feat/T-M1-01-engine-core` |

## 11. 红线（违反即返工）

1. 修改**他人写域**内的文件而未走 §5。
2. 直接编辑 `docs/word/*.docx`（必须改 md 后重新生成，D37）。
3. 未经决策记录就修改**冻结的接口契约**。
4. 把 `answer` / `steps` 下发到学生端（安全边界，C2）。
5. 在 `backend/app/engine/` 内 import 数据库、FastAPI 或任何 I/O（破坏纯函数，C5）。
6. 在持怀疑态度时「先让代码跑起来」而绕过测试。
7. 声称完成但不提供可复现命令与原始输出。
8. 引入外部网络依赖（CDN、在线字体、外部 API），破坏离线可用（C1）。
