# 07 · 老师端设计规范（M3.5）

> **状态**：v1.0 冻结（D67）　**适用**：`frontend/src/**` 的老师端界面
> **令牌唯一来源**：`frontend/src/design/tokens.css`（**Lead 维护，实现方只读**）
> **视觉方向**：**C1「工作台」为主 + 吸收 C2 的纸面质感**（用户定案，D62/D63；样张见 `frontend/mockups/`）

---

## 1. 为什么需要这份规范

M2 交付的老师端「能用但简陋」，实测根因不是审美而是**没有体系**：

| 实测 | 后果 |
| --- | --- |
| 950 行 CSS 挤在一个文件、无分层 | 改一处不知道会牵动哪里 |
| 只定义 14 个自定义变量，却混着 **33 处硬编码颜色** | 改一次主色要手工改多处，且必然改漏 |
| 没有组件层 | 按钮 / 输入 / 表格 / 卡片各写各的，状态（hover/disabled/loading）不一致 |

**规范要解决的是这三条**，美观是顺带结果。

---

## 2. 边界：什么属于本规范，什么不属于

| | 归谁 | 说明 |
| --- | --- | --- |
| **应用外壳**：顶栏、左侧题目列表、右侧排版面板、底部状态条、浮动工具栏、桌面画布 | **本规范** | React 负责 |
| **卷面本身**：A4 纸面、卷头栏、题目排布、答题横线、答案版 | **后端 `app/render/`**（D56 / C3） | 前端**不得**自己画卷面；预览一律是 `<iframe src="/api/papers/{id}/sheet">` |

两套 CSS 变量**不得混用**：

| 用途 | 变量 | 定义处 |
| --- | --- | --- |
| 应用外壳 | `--mg-*` | `frontend/src/design/tokens.css`（本规范） |
| 卷面排版六参数 | `--cols-per-row` / `--row-gap` / `--font-size` / `--page-margin` / `--answer-line-display` / `--header-bar-display` | `backend/app/contracts/layout.py`（后端契约） |

> 外壳令牌统一带 `--mg-` 前缀就是为了**避免与卷面变量撞名**。谁都不许在应用外壳里定义或覆盖卷面的六个变量。

## 3. 设计令牌

全部定义在 `frontend/src/design/tokens.css`，分八类：

| 类别 | 前缀/示例 | 取值来源 |
| --- | --- | --- |
| 桌面 / 画布 | `--mg-desk-1/2`、`--mg-desk-ambient`、`--mg-desk-vignette`、`--mg-desk-grid-*` | C1 底色 + **C2 的环境光/压暗/极淡网格** |
| 表面与墨色 | `--mg-paper`、`--mg-surface*`、`--mg-ink` / `-soft` / `-faint` | C1 |
| 主色与语义色 | `--mg-primary`、`--mg-accent`、`--mg-success`、`--mg-danger` | C1（强调色赭橙，**克制使用**） |
| 顶栏 / 状态条 | `--mg-topbar-*`、`--mg-statusbar-*` | C1 |
| 描边三级 | `--mg-line` / `-strong` / `-faint` / `-track` | C1 |
| 圆角 | `--mg-radius-float` 8px、`--mg-radius` 6px、`-sm` 5px、`-pill` | C1 |
| 阴影 | `--mg-shadow-float`（C1）、`--mg-shadow-paper`（**C2 三层投影**） | 两者合并 |
| 排版 | `--mg-font-ui` / `-paper` / `-mono`、`--mg-fs-10..16`、`--mg-fw-*`、`--mg-lh-*` | 通用阶梯 |
| 间距 | `--mg-sp-1..12`（4px 基准） | 通用阶梯 |
| 尺寸 / 层级 / 动效 | `--mg-topbar-h`、`--mg-side-w`、`--mg-z-*`、`--mg-motion`、`--mg-focus-ring` | C1 实测 |

**字体只能使用系统字体**（NFR-9 离线）：不得引入网络字体，不得使用 `@font-face` 指向外部。

## 4. 组件清单与必备状态

每个组件**必须**具备列出的状态，且状态样式一律取自令牌。

| 组件 | 必备状态 | 关键约定 |
| --- | --- | --- |
| `Button`（普通 / 主色 / 危险） | 默认 / hover / active / **disabled** / **focus-visible** | 主色按钮用于页面级唯一主操作（如「打印题目版」）；危险色只用于不可逆操作 |
| `IconButton` | 默认 / hover / focus-visible / disabled | 必须有 `aria-label` |
| `Input` / `NumberInput` | 默认 / focus / disabled / **invalid** | `invalid` 必须同时给出**文字原因**，不能只变红 |
| `Switch` | on / off / disabled / focus-visible | 文案用**人话**（「保留 / 不留」），不得显示 `block`/`none` 之类的值 |
| `Slider` | 默认 / dragging / disabled / focus-visible | 必须显示当前数值与量纲（`4 题/行`、`2.0 cm`） |
| `SegmentedControl`（预设） | 选中 / 未选 / disabled | 用于「紧凑 / 常规 / 宽松」这类互斥选择 |
| `List`（题目列表） | 空 / 有数据 / 斑马纹 / hover 行 | 每行操作不超过 2 个；序号右对齐等宽 |
| `Table`（卷库） | 空 / 有数据 / loading / 分页 | 表头与数字列对齐；空态给**下一步动作**而不是只写「暂无数据」 |
| `Card` / `FloatingPanel` | 默认 / 可折叠 / 收起 | 浮动层用 `--mg-radius-float` + `--mg-shadow-float` |
| `Toolbar` | 默认 / 分组分隔 | 浮于画布之上，**不得压住纸面**（几何断言，见 §6） |
| `StatusBar` | 默认 / 保存中 / 已保存 / 失败 | 见 §5「不谎报」 |
| `Badge` / `Chip` | 默认 / 语义色 | 卷号、题量、状态 |
| `EmptyState` / `ErrorState` | — | **必须给出可执行的下一步**或错误码，不得白屏 |
| `Toast` / 行内提示 | info / success / warning / error | 错误必须可辨识、可关闭 |

## 5. 交互约定

| # | 约定 | 理由 |
| --- | --- | --- |
| I1 | **键盘全程可达**：Tab 顺序即视觉顺序；所有可点元素有 `focus-visible` 环（`--mg-focus-ring`） | 老师备课要反复操作，鼠标不是唯一路径 |
| I2 | **不谎报状态**：任何「已保存 / 已刷新 / 已完成」文案，必须在该动作**真的成功后**才显示 | D59 的教训——界面曾显示"已保存"而预览没变 |
| I3 | **失败要说人话 + 给下一步**：错误提示包含「发生了什么」与「怎么办」 | 「TimeoutError」对老师没有意义 |
| I4 | **不可逆操作要明示**：如已发布卷的只读项，要写清「已发布 · 不可改」而不是让控件变灰了事 | 静默禁用会让人以为是 bug |
| I5 | **过渡时长取 `--mg-motion`**，并尊重 `prefers-reduced-motion` | 无障碍 |
| I6 | **预览区与打印/PDF 同源**：一律 iframe 加载后端 `/sheet`（D56），排版改动写 iframe 的 CSS 变量 | C3 |

## 6. 可判定的验收判据

规范的价值在于**能被机器检查**。M3.5 每轮的验收至少覆盖：

| # | 判据 | 检查方式 |
| --- | --- | --- |
| A1 | **令牌之外不得有颜色字面量**：`frontend/src/**` 除 `design/tokens.css` 外，不得出现 `#rgb` / `#rrggbb` / `rgb(` / `rgba(` | 脚本扫描（允许清单须逐条给理由）。**这条直接对着 M2 的 33 处硬编码来** |
| A2 | 组件必备状态齐全 | 逐组件断言状态类在样式表中存在且取值来自令牌 |
| A3 | 键盘可达 + 焦点可见 | Playwright：Tab 走一遍关键操作路径；断言 `:focus-visible` 环存在 |
| A4 | 不谎报状态 | 断言「已保存」类文案与真实请求结果同现（复用 D59 的判据） |
| A5 | 零外部资源（NFR-9） | 沿用现有位置感知的 `verify-no-cdn.mjs` |
| A6 | 预览仍来自后端 `/sheet` | 沿用现有 D56 断言 |
| A7 | 浮动层不互相压住、不压住纸面 | 几何断言（矩形不相交），沿用样张阶段的做法 |
| A8 | 1440×900 与 1280×900 下不横向溢出 | `scrollWidth == innerWidth` |
| **A9** | **预览必须是「打印几何的均匀缩放」，不得压扁** | 纸面按**真实 A4 尺寸**渲染（210mm = 794px @96dpi），再由外层**整体等比缩放**（`transform: scale(k)`）适配画布。<br>**判据**：纸内已知长度与纸宽的比值，在预览里必须等于打印时的比值。<br>例：2cm 页边距 → `75.59 / 794 = 0.0952`。**若 `75.59 / 459 = 0.165` 即判失败**（内容被横向压扁，题面会异常换行，与打印不一致） |

> **A9 是"看图"补出来的**（D68）。A1–A8 全绿时，预览仍有一个真缺陷：
> 卷面屏幕 CSS 用 `width: 210mm; max-width: 100%` —— 纸被**压到容器宽度**，
> 而 `padding` / `font-size` 仍是绝对长度，于是内容区从 210mm 缩到 459px 而字号没缩，
> 4 列每题只剩 77px（`243 × 12 ____` 需要约 118px）→ **题面异常换行**。
> 屏幕上是乱的、打印出来是好的——**正是 C3 要防的「预览 ≠ 打印」**。
> 教训：**外框比例对，不等于内几何对**。判据要盯住"纸里的东西"，不能只盯"纸本身"。

## 7. 版式骨架（C1「工作台」）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏  44px：品牌 · 导航（出题配置 / 卷库）·        后端连接状态 │
├────────────┬────────────────────────────────┬────────────────┤
│ 左：题目列表 │ 画布：桌面质感 + A4 纸面（居中）  │ 右：排版面板     │
│ 300px       │  浮动工具栏贴纸面顶部            │ 300px          │
│ 每行：序号   │  ↑ 卷面由后端渲染（iframe）      │ 预设 + 分组控件  │
│ 算式·答案    │                                 │                │
│ 换一题/删除  │                                 │                │
├────────────┴────────────────────────────────┴────────────────┤
│ 状态条 34px：题目 40 道 · 页码 1/1 · 每行 4 题共 10 行 ·        │
│              种子 · 已保存，预览已刷新 · 纸面 210×297mm(A4)     │
└──────────────────────────────────────────────────────────────┘
```

- 纸面按 **A4 真实比例**（`210/297`）呈现，按剩余高度缩放；**不得**再出现"横向扁块漂在灰底上"（D62 的实测缺陷）
- 1280 宽下左侧与右侧收窄到 `--mg-side-w-narrow`，次要元数据（种子等）可隐藏
- 桌面质感 = 主色渐变 + 环境光 + 底部压暗 + `--mg-desk-grid-*` 极淡网格

## 8. 两轮实现的分工

| 轮次 | 做什么 | 不做什么 |
| --- | --- | --- |
| **结构轮** | 引入 `tokens.css` 并**全量替换**硬编码；抽出组件层；统一所有组件的状态；骨架改为 C1 版式 | **不做视觉打磨**（不调阴影/间距的观感），目标是"有纪律"而非"好看" |
| **视觉轮** | 在结构轮之上做观感：桌面质感、纸面投影、层次、微交互、密度微调 | 不改组件 API、不改骨架 |

每轮结束由 **verify 独立验收**（按 §6 判据），**用户看图确认**（"好看"是主观的，必须由人拍板）。

## 9. 变更规则

`tokens.css` 是冻结契约，与 `backend/app/contracts/**` 同级治理：

1. 需要增删改令牌 → **先在 `docs/00-决策记录.md` 新增决策**，说明理由与影响面
2. 由 Lead 改 `tokens.css`，并更新 `docs/07` 与守卫（A1 的允许清单）
3. 实现方**只读**该文件；需要新令牌时提出，不得自行添加
