# 老师端视觉方向样张

**这是设计探索，不是实现。** 所有文件都是**自包含静态原型**（CSS 内联、零外部资源、无 JS 依赖），
用来和用户确认「界面优化往哪个方向走」；选定方向后再另开任务做真正的实现。

## 怎么打开

**双击任一 HTML 即可**（`file://` 直开，不需要任何服务器、不联网）：

| 文件 | 方向 | 一句话 |
| --- | --- | --- |
| [`option-a-minimal.html`](option-a-minimal.html) | 极简克制 | 工具感：近黑白、1px 边框分层、信息密度优先 |
| [`option-b-friendly.html`](option-b-friendly.html) | 卡片圆润 | 亲和感：明快青蓝、大圆角、浅色卡片分区 |
| [`option-c-canvas.html`](option-c-canvas.html) | 纸张隐喻 | 画布感：灰桌面上一张纸，工具栏与面板是浮动层 |
| [`option-c1-workbench.html`](option-c1-workbench.html) | **C1 工作台** | 选定 C 后的细化：常驻列表 + 状态条 + 分组面板，把空间用功能填满 |
| [`option-c2-focus.html`](option-c2-focus.html) | **C2 聚焦** | 选定 C 后的细化：缩略图轨道 + 桌面质感，留白是有意的 |

> **用户已选定 C（纸张隐喻）**，并反馈「整个页面有点空旷」。
> C1 / C2 是同一方向的两种「怎么处理空间」的方案；A / B 作为对照保留。
> 原 `option-c-canvas.html` 保留为历史对照 —— 它有两个客观缺陷（见下节），已被 C1/C2 修正。

所有样张**内容一致**，便于公平比较：同一套 40 道题、同一张 A4 卷面（4 列 + 答题横线 + 卷号 `2610-0001`）、
同样的排版六项与状态文案。题目文本取自 M2 验收产物里的真实卷面，不是编的。

## C 原版被实测出来的两个客观缺陷（C1/C2 已修）

| 缺陷 | 原版实测 | 修正后 |
| --- | --- | --- |
| 纸面比例不是 A4 | `width: 560px` 且**没有 height** → 渲染成 560×333，比例 **1.68（横版）** | `aspect-ratio: 210 / 297` + 按可用高缩放 → 实测 **0.7071**（A4 = 0.7071） |
| 纸面只画了 24 格 | 4 列 × 6 行 = 24 格，标称 40 题 → 下半页空着 | 4 列 × **10 行 = 40 格**，题块纵向占纸高 0.62–0.68，一页填满 |

还有一处顺带修掉的：原版纸面被顶部工具栏压住（`height:100%` 在 flex 里溢出父盒）。
C1/C2 改成「工具栏在舞台里占位、纸按剩余高度缩放」，并新增了一条**浮动层互不压住**的几何断言。

## C1 与 C2 的差别（只在「怎么处理空间」）

| | **C1 工作台** | **C2 聚焦** |
| --- | --- | --- |
| 左侧 | **常驻题目列表**（40 题，每行「换一题 / 删除」）—— 改题是最高频操作，不该藏在抽屉里 | **页面缩略图 + 页码**（40 题 1 页），不做列表 |
| 灰底留白 | 尽量用功能填：**底部状态条**（题量 / 页码 / 行数 / 种子 / 保存状态） | 保留留白，但用**桌面质感**（顶部环境光渐晕 + 底部压暗 + 极淡网格 0.10）+ 纸面**三层强投影** |
| 工具栏 | 贴纸面顶部；含**缩放控件**（适应宽度 / 100%）+ 文件与打印动作 | 同样贴纸面顶部，更精简（无「新建一套 / 去发卷」，只留缩放与打印） |
| 右侧面板 | 六项分「**版面**」「**元素**」两组 + **预设**（紧凑 / 常规 / 宽松） | 六项平铺，仅收紧与纸面的距离 |
| 屏幕利用率 | 高：三块功能区把灰底填满 | 中：刻意留白，靠质感与投影让灰底读成「桌面」 |
| 适合 | 一次要改很多题、频繁换题的老师 | 出题后主要看版式与打印，改题是间歇动作 |

两版都保留 C 的身份：**灰桌面 + 纸面居中 + 浮动层（8px 圆角）**。

## 对比表（三个方向）

| | **A 极简克制** | **B 卡片圆润** | **C 纸张隐喻** |
| --- | --- | --- | --- |
| 圆角 | 4–6px | 10–14px（卡片）/ 999px（按钮、开关） | 8px，**只给浮动层** |
| 阴影 | 几乎不用，靠 1px 边框分层 | 柔和多层（`0 2px 8px` + `0 8px 20px` 双色） | 画布上强投影，模拟「纸在桌上」 |
| 主色 | 近黑白 + 一个克制强调色（蓝），只用于选中态与当前值 | 明快青蓝主色 + 浅色背景块（`#e8f1fe` / `#eafaf3`） | 中性灰桌面 + 纸白；近黑为功能性主色，暖色仅点缀卷号/当前值 |
| 间距 | 紧凑：行高 1.45、行内 padding 3px | 宽松：行高 1.55、行内 padding 9px、按钮 999px 大点击区 | 画布留白大；面板与工具栏紧凑居中 |
| 布局 | **三栏等重**（左列表 / 中纸面 / 右面板） | 卡片分区：顶部信息卡 + 三张卡片（列表 / 预览 / 面板） | 纸面居中占主；两侧是浮动层（C1 列表常驻 / C2 缩略图轨道） |
| 字体 | 系统无衬线，数字用等宽对齐 | 系统无衬线，数字加粗 + 绿色高亮 | 卷面用宋体（与打印一致），界面用无衬线 |
| 目标感受 | 熟练用户、快 | 非技术用户、不慌 | 「我在排一张卷子」 |
| 实现代价 | 最低（几乎等于把现有 CSS 收紧 + 统一 token） | 中（需要卡片/开关/按钮三类组件与设计 token） | 最高（画布、浮动层、折叠交互，等于一套新布局） |
| 与"打印所见即所得"的关系 | 中性：界面克制，纸面是纸面 | 界面较"产品化"，纸面仍准确 | **最贴题**：视觉隐喻直接指向"排卷子/打印" |

## 什么情况下选哪版

**选 A 极简克制**，如果
- 目标用户是**熟练老师**，一天要出好几套卷，追求「少点一次是一次」；
- 团队想**先收敛再美化**：这版最接近现有实现的演进路径（可先统一设计 token、去硬编码颜色，不引组件库）；
- 在意**信息密度**：40 题列表与六项排版面板同屏可见，不靠折叠。

不适合：如果用户的原话是「太简陋」，A 的克制可能仍被读成「简陋」——它靠排版纪律而非装饰取胜。

**选 B 卡片圆润**，如果
- 目标用户**不太懂技术**、对密集界面发怵，需要「看起来像个正经产品」；
- 团队决定**引入组件库**（Mantine / Ant Design 等）——B 的形态最容易映射到现成组件（Card / Switch / Slider / Badge）；
- 需要**大点击区域**（触屏笔记本、老教师）。

不适合：卡片 + 圆角 + 阴影会吃掉不少屏幕，1440×900 下三列已接近极限；40 题列表要滚动更多。

**选 C 纸张隐喻**（用户已选），如果
- 产品定位强调**「这是排卷子、要打印」**（FR-T5/T6 是核心价值），愿意为这个隐喻付出布局复杂度；
- 用户会**先看纸面再调参**——纸面居中占主最符合这个动作顺序。

选定 C 之后再看 C1 / C2：**改题频繁选 C1，改题偶尔选 C2**（对照表见上文）。

## 这些样张都不是最终态

- **都没有做手机适配**——桌面端为主（老师用笔记本），学生端在 M4。
- 都只画了**预览改题页**一个页面；出题配置页、卷库页沿用同一套视觉语言即可。
- 交互只有示意：A / B 的滑块与开关是静态的；C 的抽屉用纯 CSS checkbox 真的可点（无 JS）；
  C1 / C2 的预设、缩放按钮同样是静态示意。
- 目标视口 **1440×900**；所有样张在 **1280×900** 下都没有横向溢出（见 `shot-*-1280x900.png`）。

## 自检（可复现）

```powershell
# ① 零外部资源 + ② 内容一致（纯标准库，不开浏览器；覆盖全部 5 个样张）
& backend\.venv\Scripts\python.exe frontend\mockups\check-mockups.py
# → 结果：29/29 通过

# ③ 手动确认没有外部引用（等价的一行 grep，命中即失败）
Select-String -Path frontend\mockups\*.html -Pattern 'https?://|//cdn|@import\s+url\(|<link|<img|<script\s+src'
# → 无输出
```

> `check-mockups.py` 只用标准库，任何装了 Python 的机器都能跑；
> 它校验「所有样张必含同一批内容」（导航 / 40 题 / 卷面卷头 / 六项控件 / 两条状态文案），
> 避免将来只改一版导致没法公平比较；对 C1/C2 额外要求卷面 40 格。
>
> **浏览器侧的几何验收**（C1/C2 各 1440×900 与 1280×900 共 4 组）用 Playwright 跑过 **44/44 通过**：
> 纸面比例实测 **0.7071**（A4 = 210/297 = 0.7071）、按题块顶边分组得到 **10 行**、**40 格**、
> 40 个题块全部落在纸面内、题块纵向占纸高 0.68 / 0.64、`scrollWidth == innerWidth`、
> 浮动层之间互不压住、无控制台报错。该脚本是一次性的（用完即删），需要复跑时按同样方式量
> `getBoundingClientRect()` 即可。
